# 版本记录：v0.47-homepage-visual-closure

## 1. 本轮目标

本轮要解决的问题已经不只是 Hero 风险矩阵的视觉回退，而是首页整体出现了以下上线前收口问题：

- 风险提示条缺少预警锚点
- 风险卡退回普通统计卡气质
- 首页部分卡片高度不齐
- 标题、说明、按钮底边节奏不统一
- 页面看起来像多个模块拼接，而不是同一套判断平台

本轮属于：

- 首页视觉收口
- 信息层级修正
- 卡片系统统一
- 上线前稳定性整理

## 2. 背景与上下文

本轮承接：

- `custom/notes/v0.40-hero-risk-panel-final-alignment.md`
- `custom/notes/v0.41-hero-risk-panel-width-and-text-closure.md`
- `custom/notes/v0.42-hero-risk-matrix-restoration.md`

延续结论：

- 首页首屏必须保持“左侧主叙事 + 右侧风险判断”的结构
- 右侧不能空白，但也不能变成第二个 Hero
- 首页节奏必须更像连续信息流，而不是模块拼图

## 3. 问题分析

表面现象：

- 顶部风险提示条不再有明显预警感
- 风险卡数字和卡面层级不足
- 案例卡、方案卡、分类卡的标题和说明高度不统一
- 中部流程卡与上方卡片节奏不一致

核心矛盾：

首页现在的问题并不是“缺一个功能”，而是“同一页里的信息承载块没有统一成一套系统”。

如果只修一张卡，页面仍然会显得松散；必须把 Hero、卡片、标题说明和流程节奏一起收口。

## 4. 候选方案比较

### 方案 A：只修 Hero 风险矩阵

优点：

- 改动最小

缺点：

- 中下段卡片节奏仍然松散
- 首页整体仍会显得像多模块拼接

结论：

放弃。

### 方案 B：在不改首页结构的前提下，同步收口 Hero 与首页核心卡片系统

优点：

- 能一次解决首屏和中段的不统一问题
- 不需要重构页面结构
- 风险低，验证成本可控

缺点：

- 改动会涉及多个首页组件

结论：

采用。

## 5. 最终决策

最终采用“局部多点收口”的方式：

1. 恢复 Hero 风险提示条的预警视觉锚点
2. 恢复风险卡的数字层级和预警卡面板感
3. 统一 SectionTitle 的标题与说明节奏
4. 统一首页案例卡、方案卡、分类卡、问题卡、流程卡的高度和底边关系
5. 保持首页结构不变，只修内容呈现和排版系统

## 7. 本轮优点

- Hero 风险模块重新回到“风险预警面板”气质
- 首页中段卡片系统更统一
- 标题、说明、按钮底边的视觉关系更稳定
- 首页整体更像同一套判断平台，而不是多个独立模块

## 8. 本轮缺点与代价

- 本轮主要收口的是首页，不代表其它页面的卡片系统已经完全统一
- 当前没有在本轮里继续处理更多详情页的版面细节
- 由于遵守“不重构”原则，仍然保留了现有组件边界，后续如果继续做全站统一，可能还要抽更底层的卡片样式约束

## 10. 本轮结论

首页当前最需要的不是新增模块，而是把现有内容统一成一套稳定、克制、专业的展示系统。

只修 Hero 不够，必须连同首页主要卡片系统一起收口，页面才不会继续显得散。

## 11. 下一轮建议

1. 用浏览器继续复核首页桌面端 1440 / 1536 宽度下的实际观感，重点看 Hero 与案例区是否还存在局部挤压
2. 若继续收口，优先统一 `CtaBlock`、`Footer` 与首页卡片系统的圆角、留白和按钮节奏
3. 如需继续提升稳定感，下一步再处理方案页和知识详情页的卡片与正文节奏统一
