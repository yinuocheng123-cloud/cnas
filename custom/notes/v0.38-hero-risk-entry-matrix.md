# 版本记录：v0.38-hero-risk-entry-matrix

## 1. 本轮目标
本轮只处理首页 Hero 右侧区域。

核心目标：
- 恢复首屏右侧的信息承载能力
- 增加风险证据感和可点击入口
- 不恢复大图片
- 不做结构性重设计

本轮属于：
- 首页首屏收口
- 风险入口增强
- 转化入口前置

## 2. 背景与上下文
本轮承接：
- `custom/notes/v0.37-risk-driven-decision-platform-refinement.md`
- `custom/notes/v0.36-decision-driven-website-refactor.md`

延续结论：
- 首页已经切到“风险判断平台”方向
- Hero 左侧文案已具备较强的判断感
- 当前最大问题在于右侧过空，缺少视觉锚点、风险证据和点击入口

## 3. 问题分析
修改前的 Hero 右侧主要有三个问题：

1. 信息密度过低
- 左侧已经讲风险，右侧却几乎没有承接，导致首屏重心偏左。

2. 缺少“证据感”
- 用户能读到风险判断，但看不到任何看似来自真实场景的结果入口。

3. 缺少点击入口
- Hero 首屏的行动主要依赖左侧按钮，右侧没有形成辅助承接。

核心矛盾不是视觉不好看，而是右侧没有承担“风险证据入口”的职责。

## 4. 候选方案比较
### 方案 A：恢复图片或大视觉区
- 优点：视觉上更饱满。
- 缺点：会削弱当前的专业、克制和非宣传片风格。
- 结论：放弃。

### 方案 B：做风险结果入口矩阵
- 优点：不依赖图片，也能承载数字、风险结果和跳转入口。
- 缺点：对文案精度要求更高。
- 结论：采用。

## 5. 最终决策
最终采用“2×2 风险入口矩阵”。

关键决策：
- 桌面端使用 2 列 2 行
- 移动端自动单列
- 每张卡片只保留数字、标题、一句结果说明和链接
- 保持克制的卡片风格，避免数据大屏或仪表盘感

## 6. 具体实现
### `src/data/riskEntries.ts`
- 新增 Hero 风险入口矩阵数据
- 统一维护数字、标题、摘要和跳转链接

### `components/RiskEntryCard.tsx`
- 新增轻量风险卡片组件
- 保持统一样式和点击状态

### `lib/site-data.ts`
- 转发 `riskEntries` 数据，保持与其他首页数据一致的读取方式

### `app/page.tsx`
- 在 HeroSection 中传入右侧 `aside`
- 使用 2×2 风险矩阵承接首页首屏右侧

### `components/HeroSection.tsx`
- 仅微调右侧 aside 宽度和 risk notice 行高
- 不改 Hero 主结构

## 7. 本轮优点
- Hero 右侧从“空白区”变成“风险证据入口”
- 首屏可点击入口更丰富，但仍保持克制
- 信息更平衡，左侧判断、右侧证据的分工更清晰

## 8. 本轮缺点与代价
- 数据仍是内容型证据，不是真实后台统计
- 后续如果要继续增强可信度，可以再补更细的专题入口页

## 9. 验证与结果
计划执行：
- `npm run typecheck`
- `npm run build`
- `npm run dev`

重点检查：
- 首页首屏矩阵显示
- 移动端单列布局
- Hero 风险提示与矩阵的对齐关系

## 10. 本轮结论
- 首页 Hero 右侧不一定需要图片，只要有足够清晰的风险入口，也能形成证据感。
- 当前矩阵方案更符合站点“专业、克制、可信”的定位。

## 11. 下一轮建议
1. 若后续继续增强可信度，可为矩阵中的每一类风险单独补一篇专题文章。
2. 可在案例页顶部增加“按返工类型筛选”的轻量入口。
