# 版本记录：v0.35-industry-taxonomy-unification

## 1. 本轮目标
本轮目标不是重构页面，而是在现有结构上把行业入口统一起来。

核心要解决的问题：
- 行业方案已经存在，但导航、诊断表单、首页方案区、CTA 和推荐逻辑没有共用同一个行业源
- 新能源 / 储能实验室虽然已经有方案页，但缺少统一入口体系
- 行业名称仍散落在静态数据和页面实现里，后续扩展成本高

本轮属于：
- 数据结构统一
- 行业入口体系收口
- 转化路径一致性提升

## 2. 背景与上下文
本轮承接：

- `custom/notes/v0.40-hero-risk-panel-final-alignment.md`

延续约束：

- 不修改现有 URL
- 优先数据驱动

## 3. 问题分析
修改前的行业体系存在三个核心问题：

1. 行业名称多处硬编码
- 导航下拉、诊断表单和方案页列表没有共用同一个行业源
- 新增行业时，需要在多个地方同步补字面量

2. 方案数据和行业入口脱节
- `solutions` 中已经有完整方案数据
- 但首页、导航和推荐逻辑仍没有用“行业实体”来驱动顺序和关联

3. 转化路径不统一
- CTA 文案、推荐逻辑和诊断入口没有显式体现“行业对应路径”
- 用户很难感受到这是长期运营的平台，而更像拼接的页面集合

## 4. 候选方案比较
### 方案 A：继续在各页面补硬编码
- 优点：改动最小
- 缺点：后续扩展仍然分散，和本轮目标相反
- 结论：放弃

### 方案 B：建立统一行业实体源，并向下兼容接入现有结构
- 优点：能统一入口、顺序、表单选项与推荐逻辑
- 缺点：需要跨多个页面和数据文件同步改动
- 结论：采用

## 5. 最终决策
最终采用新增 `industry-taxonomy` 的方式统一行业体系：

1. 新增 `lib/industry-taxonomy.ts`
2. 让导航“行业方案”下拉从 taxonomy 读取
3. 让诊断表单“企业类型”从 taxonomy 读取
4. 让首页和方案列表按 taxonomy 顺序展示
5. 让方案卡 tags 和详情页相关推荐从 taxonomy 和方案数据联动

### `app/page.tsx`

- 使“新能源 / 储能实验室”进入首页主方案体系，并排在制造、第三方之后

### `components/CtaBlock.tsx`

  - 开始路径诊断
  - 获取实验室认可路径
  - 查看行业案例

## 7. 本轮优点
- 行业入口真正有了单一数据源
- 新能源 / 储能实验室不再只是孤立页面，而是完整接入导航、首页、诊断和推荐路径
- 方案卡 tags、相关推荐和 CTA 形成更强的平台一致性
- 后续新增行业时，不再需要到处补硬编码

## 8. 本轮缺点与代价
- 当前导航的一级结构仍沿用原有 `navItems` 框架，没有把所有导航都完全拆成更细的 taxonomy 驱动
- 方案正文内容本身仍保留在 `site-data.ts` 中，taxonomy 只负责行业实体层，不负责全部业务文案
- 仍有部分行业名称出现在方案标题和正文里，这是为了保持现有 URL 与页面语义不变

## 10. 本轮结论
- 对当前站点来说，“统一行业实体源”比继续补入口更重要
- 当导航、表单、列表、推荐都共用同一行业源后，整站会明显更像长期运营平台，而不是临时拼接网站
- 新能源 / 储能实验室这一类高投入场景，只有接入统一入口体系后，才真正具备承接能力

## 11. 下一轮建议
1. 如果后续继续扩行业，优先只在 `industry-taxonomy.ts` 和 `solutions` 数据中补充
2. 可继续把案例与知识库按行业挂接到 taxonomy，形成更强的推荐链
3. 若后续需要更细行业运营，可以再补“按行业筛选案例 / 文章”的轻量入口
