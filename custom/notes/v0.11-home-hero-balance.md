# 版本记录：v0.11-home-hero-balance

## 1. 本轮目标

本轮目标是优化首页首屏版式比例，降低左侧标题压迫感，让标题、补充句、按钮、风险提示和右侧数据卡片形成更平衡的视觉高度。

目标类型：视觉比例优化、首屏层级收口。

## 2. 背景与上下文

本轮承接 `custom/notes/v0.10-home-title-closure.md`。上一轮已将首页标题收口为两行结构，本轮继续调整字号、行高、间距和按钮厚度，不改变导航结构、不新增复杂功能。

## 3. 问题分析

首页首屏左侧标题在桌面端视觉重量偏大，三层文字之间层级不够明显，左侧内容高度也容易高于右侧三张价值卡片，导致左右信息比例略失衡。

核心矛盾是：首屏需要保留决策入口的清晰表达，但不能让标题区域显得过满。

## 4. 候选方案比较

方案一：直接全局缩小 Hero 标题。

优点是实现简单。缺点是会影响其他页面 Hero，不符合本轮只优化首页首屏的边界，因此放弃。

方案二：为 Hero 增加轻量 `balanced` 变体，只在首页使用。

优点是能局部控制首页首屏尺寸、间距和风险提示样式，同时保持其他页面不变。缺点是组件多一个可选变体。最终选择该方案。

## 5. 最终决策

新增 `variant="balanced"`，用于首页首屏：降低主标题字号，第二行使用相对字号继续缩小，第三行作为弱辅助句处理；同时收紧按钮、描述和风险提示间距。

## 6. 具体实现

修改 `components/HeroSection.tsx`：增加 `variant` 属性，并为 balanced 模式设置更小的标题、较窄 max-width、更紧凑 padding、更轻的风险提示样式和更居中的左右对齐。

修改 `app/page.tsx`：首页 Hero 使用 balanced 变体，第二行标题缩小，按钮尺寸收紧，副按钮样式变轻。

## 7. 本轮优点

首屏三层结构更清楚：主标题强、关键句中、补充句弱。左侧内容不再显得过满，按钮和风险提示也从强模块回到辅助信息。

## 8. 本轮缺点与代价

当前仍然是静态布局优化，没有通过截图工具做像素级对齐校验。移动端主要依赖响应式字号、换行和按钮自动换行控制。

## 9. 验证与结果

本轮需要执行 `npm run typecheck`、`npm run build`，并验证首页 `/` 返回 200。

## 10. 本轮结论

首页首屏已从“大标题压迫型”收敛为更平衡的决策入口布局，整体更克制。

## 11. 下一轮建议

下一步如继续优化，应优先基于真实截图微调桌面端左右卡片高度和移动端首屏高度。
