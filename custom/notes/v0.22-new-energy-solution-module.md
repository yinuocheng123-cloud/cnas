# 版本记录：v0.22-new-energy-solution-module

## 1. 本轮目标

本轮目标是在现有行业方案体系中新增“新能源 / 储能检测实验室”模块，并保证它在内容气质上比普通行业方案更强调“高要求、先判断、易重复投入”的专业感。

本轮优先级属于：

- 内容补充
- 行业方案扩展
- 转化承接增强

## 2. 背景与上下文

本轮承接以下记录：

- `custom/notes/v0.21-logo-brand-integration.md`
- `custom/notes/v0.16-diagnosis-conversion-enhancement.md`

当前站点已经具备行业方案列表与详情页结构，行业方案数据集中在 `lib/site-data.ts` 的 `solutions` 数组中，并通过 `/solutions` 与 `/solutions/[slug]` 自动渲染。

用户本轮要求新增“新能源 / 储能检测实验室”，并明确希望它使用判断型结构，而不是普通介绍型结构。由于当前详情页已经固定使用 `summary / suitableFor / commonProblems / recognitionDifficulties / buildPath / assessmentRisks / solutionReference` 这一套字段，本轮不新增数据结构，而是在现有字段内完成判断型内容映射。

## 3. 问题分析

当前行业方案虽然已经覆盖制造企业、检测机构、高要求实验室、高校科研和集团内部实验室，但缺少新能源 / 储能这一类更容易出现高投入、高风险、高技术门槛的检测场景。

这个模块的核心矛盾不是“有没有实验室”，而是：

1. 检测项目范围往往更复杂，涉及电性能、安全性、循环性能等多维指标。
2. 企业容易在未收敛能力边界前就先投入设备和场地。
3. 一旦设备配置、环境条件或人员经验与关键检测项不匹配，后续返工成本明显更高。

因此，本轮内容必须把“先判断，再建设”的顺序放得比一般方案更靠前。

## 4. 候选方案比较

### 方案一：新增独立的数据结构，专门为新能源模块写“问题说明 / 关键判断 / 常见误区 / 简要建议”

优点：

- 和用户提供的原始结构最一致
- 语义最直接

缺点：

- 需要改动详情页组件
- 会打破当前所有行业方案共用的数据驱动模式
- 超出本轮“只做内容扩充”的边界

放弃原因：结构成本过高，不符合当前项目模式。

### 方案二：沿用现有方案字段，把判断型结构映射进去

优点：

- 不需要改组件
- 新增后自动进入列表页、详情页和 sitemap
- 风格与现有方案保持一致

缺点：

- 需要把用户提供的四段内容拆分映射到多个字段

最终选择原因：最符合当前项目的数据驱动模式，也最稳。

## 5. 最终决策

本轮最终采用以下方式：

1. 在 `solutions` 数组中新增 `new-energy-lab`
2. 放在“制造企业实验室”“检测机构实验室”之后，作为第三个行业方案
3. 将用户要求的四段结构映射为：
   - `summary`：问题说明与前置提醒
   - `recognitionDifficulties`：关键判断
   - `assessmentRisks`：常见误区及后果
   - `solutionReference`：简要建议与诊断引导
4. 同步更新行业方案页头部文案，让列表页也能体现新能源 / 储能的高要求属性

## 6. 具体实现

本轮修改文件如下：

- `lib/site-data.ts`
  - 新增 `new-energy-lab`
  - 设置标题为“新能源 / 储能检测实验室 CNAS认可路径”
  - 新增 `summary / suitableFor / commonProblems / recognitionDifficulties / buildPath / assessmentRisks / solutionReference`
  - 内容重点突出设备、环境、方法、安全与能力边界的前置判断

- `app/solutions/page.tsx`
  - 更新行业方案页 metadata 描述
  - 更新 Hero 描述，把“新能源 / 储能等高要求场景”纳入页面主叙事

## 7. 本轮优点

本轮带来的正向效果：

- 行业方案新增了一个明显更专业、更难的场景模块
- 内容会自然传递“高投入前先判断”的专业感
- 不改组件即可自动进入列表页、详情页和静态生成流程
- 方案结尾自然落到“如不确定，建议先做一次判断”的诊断承接

## 8. 本轮缺点与代价

本轮也有明确代价：

- 当前仍沿用现有行业方案字段，没法在页面上完全按“问题说明 / 关键判断 / 常见误区 / 简要建议”四个大标题逐段显示
- “新能源 / 储能”内部如果后续继续细分到动力电池、储能系统、材料测试等，会需要再拆更细的方案
- 现在的标签要求只在文案层吸收，没有建立独立的标签数据结构挂接到方案模块

## 9. 验证与结果

本轮完成后执行了以下验证：

- `npm run typecheck`
- `npm run build`

验证目标：

- 新方案字段满足现有 `Solution` 类型
- `/solutions/new-energy-lab` 可被正常静态生成
- `/solutions` 列表页自动展示新增模块

## 10. 本轮结论

本轮最重要的结论有三点：

1. 新能源 / 储能实验室不是普通行业扩展，而是更适合承接“高要求、高投入、高返工风险”的专业判断需求。
2. 在当前项目里，新增高价值方案模块最稳的路径仍然是沿用现有 `solutions` 数据结构，而不是临时发明新模板。
3. 对这类场景，真正有转化价值的不是“介绍行业”，而是把能力边界和投入顺序讲清楚。

## 11. 下一轮建议

1. 如继续扩充行业方案，可按同样思路补“汽车零部件 / 电池材料 / 功率电子”等细分实验室。
2. 如果行业方案继续增加，后续可考虑给 `/solutions` 增加更明确的行业分组，但这应作为单独一轮处理。
3. 若要进一步增强承接能力，可在新能源方案详情中补更细的检测项目示例，但仍建议继续走数据层扩展，不改组件结构。
