# 版本记录：v1.3-mobile-only-homepage-refine

## 1. 本轮目标

本轮目标是只修订 CNAS认可指南主站手机端首页体验，不改电脑版首页结构，不修改 `path.cnaszhinan.com`，不改 Nginx，不改后台和线索接口。

目标效果是让手机端更清爽、更可信，并自然表达“先判断路径，再决定怎么启动”，但不把成交页整块搬进主站。

## 2. 背景与上下文

本轮承接 `custom/notes/v1.2-desktop-rollback-mobile-refine.md`。上一轮已经纠正了电脑版首页成交页化的问题，并恢复了 `path.cnaszhinan.com` 独立访问。

本轮延续该结论：电脑版首页必须稳住，移动端可以轻量借鉴路径判断逻辑。

## 3. 问题分析

修复后的手机端已经比上一轮克制，但仍偏文字清单，缺少一点视觉层次；FAQ 直接展开也会让手机端显得偏长。Footer 虽然功能完整，但手机端居中和二维码可读性还可以更好。

本轮的关键不是增加更多内容，而是优化手机端的信息节奏：首屏给判断卡片，痛点短卡片化，路径判断六项更像工具清单，企业微信承接独立成块，FAQ 折叠，footer 更居中清爽。

## 4. 候选方案比较

方案一：新增手机端完整表单。

优点是转化更直接。缺点是容易再次变成长表单成交页，违背本轮“不照搬成交页”的约束。本轮放弃。

方案二：新增外部实验室图片。

优点是视觉更丰富。缺点是版权和加载风险更高，也可能让页面变重。本轮放弃。

方案三：使用 CSS 和现有二维码做轻量视觉优化。

优点是无版权风险、加载轻、只影响手机端，能改善节奏而不改变桌面端。本轮采用。

## 5. 最终决策

最终采用“移动端专属轻量视觉优化”方案。所有新增体验均通过 `md:hidden` 或移动优先样式控制，电脑版主体结构不变。

## 6. 具体实现

- `app/page.tsx`：
  - 手机首屏增加一个轻量路径判断视觉卡片，使用 CSS 卡片和文字，不新增图片文件。
  - 手机痛点模块改为三条短卡片，每条只保留标题和一句说明。
  - 手机路径判断模块改为六个小卡片，强化“实验室类型、认可范围、人员能力、设备环境、体系运行、评审准备”。
  - 手机轻量转化入口保留“开始路径判断”“添加顾问领取问卷”“查看行业路径”三个入口，不放完整长表单。
  - 新增手机端企业微信承接卡片，二维码使用 `/wecom-qr.png`。
  - 手机 FAQ 改为折叠式，并补充“现在只是了解阶段，能不能先判断路径？”。
- `components/Footer.tsx`：
  - 手机端 footer 居中展示品牌、服务内容和二维码。
  - 二维码手机端放大到 160px，桌面端仍保持 144px。
  - 备案号继续保留 `浙ICP备2020044218号-3` 和工信部链接。

## 7. 新增图片、图标或视觉元素

本轮未新增图片文件。

新增视觉元素均为 CSS/HTML 轻量卡片：

- 手机首屏路径判断卡片。
- 痛点编号圆点。
- 路径判断六项编号圆点。

继续使用既有公开资源：

- `/wecom-qr.png`

## 8. 本轮优点

- 电脑版首页结构未被再次改动。
- 手机端首屏更有判断入口感，但不是广告页。
- 手机端没有长表单，没有重复表单。
- 页面最多出现两个二维码：主体承接区和 footer。
- FAQ 折叠后页面更短。
- 未新增外部图片和第三方依赖，加载不会明显变重。

## 9. 本轮缺点与代价

本轮没有做真实手机截图自动回归，仍需要用户用真实手机最终确认视觉观感和扫码体验。

因为不新增完整表单，手机端转化仍以进入 `/diagnosis` 和添加企业微信为主，适合“指南站 + 轻转化入口”的定位。
