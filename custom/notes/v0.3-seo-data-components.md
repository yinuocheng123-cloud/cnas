# 版本记录：v0.3-seo-data-components

## 1. 本轮目标

本轮目标是在 v0.2 站点路由基础上，补齐 SEO、sitemap、robots、数据分层和基础组件体系，让站点更接近专业 B 端知识与解决方案平台。

目标类型：可维护性提升、SEO 基础建设、内容结构优化。

## 2. 背景与上下文

本轮承接 `custom/notes/v0.2-hangyu-cnas-site-routes.md`。上一轮已经完成首页、知识库、解决方案、案例、服务和关于页面。用户进一步明确了 GEO、TEO、SEO 和组件化要求，并明确本轮不做后台管理、会员登录、在线支付、复杂 CMS、真实数据库部署、复杂动画和多语言。

## 3. 问题分析

v0.2 页面已经可访问，但数据仍集中在 `lib/site-data.ts`，文章、案例、服务的内容边界不够清晰。SEO 只有基础 metadata，尚未显式提供 sitemap 和 robots。页面组件也比较分散，不利于后续扩展。

核心问题是：在不接入数据库和 CMS 的前提下，让内容结构、页面表达和搜索引擎识别能力先达到 Demo 可交付状态。

## 4. 候选方案比较

方案一：继续在 `lib/site-data.ts` 中维护所有内容。

优点是文件少。缺点是文章、案例、服务混在一起，后续接 CMS 或数据库时迁移边界不清，因此放弃。

方案二：立即接入真实数据库或 CMS。

优点是更接近长期形态。缺点是用户已明确本轮不做真实数据库部署和复杂 CMS，会引入额外依赖和配置风险，因此不采用。

方案三：拆分 `src/data/articles.ts`、`src/data/cases.ts`、`src/data/services.ts`，并通过组件统一页面展示。

优点是内容边界清晰，类型可控，后续可以逐步替换为数据库或 CMS。缺点是 Demo 阶段仍需开发者改代码维护内容。最终选择该方案。

## 5. 最终决策

最终保留本地 TypeScript 数据方案，并新增分层数据文件和通用组件。SEO 使用 `lib/seo.ts` 统一生成 title、description、canonical 和 Open Graph 基础信息。站点通过 `app/sitemap.ts` 与 `app/robots.ts` 输出搜索引擎入口。

视觉方向收敛为白底、深蓝、深灰、克制卡片和清单，不做复杂动画。

## 6. 具体实现

新增 `src/data/articles.ts`，按用户指定的 Article 类型维护三篇知识库文章。

新增 `src/data/cases.ts`，按问题、解决、结果维护三条案例。

新增 `src/data/services.ts`，按适合对象、问题、交付物、客户配合事项维护四项服务。

新增 `lib/seo.ts`，统一生成页面 metadata。

新增 `app/sitemap.ts` 与 `app/robots.ts`，显式声明主要栏目、三篇文章和三类解决方案。

新增 Header、Footer、HeroSection、SectionTitle、ArticleCard、SolutionCard、CaseCard、ServiceCard、FaqBlock、ChecklistBlock、CtaBlock、Breadcrumb 等基础组件。

更新页面引用新数据和组件，保留 App Router 静态生成能力。

## 7. 本轮优点

文章结构符合 GEO：定义清楚、问题明确、首段直接回答、结构分明、有 FAQ、有判断清单、有相关内容推荐。

页面表达符合 TEO：强调 CNAS 不是简单办证，提供风险提示、判断清单、服务边界、案例拆解和咨询入口。

SEO 基础完整：每个主要页面和动态详情页都有 metadata，sitemap 与 robots 已纳入构建。

## 8. 本轮缺点与代价

canonical 域名暂用 `https://www.hangyukeji.com`，上线前必须确认真实域名。

数据仍由 TypeScript 文件维护，不适合非技术人员长期发布内容。

当前视觉是克制型基础样式，不是完整品牌设计稿。

## 9. 验证与结果

已执行 `npm run typecheck`，结果通过。

已执行 `npm run build`，结果通过。构建输出包含 `/sitemap.xml`、`/robots.txt`、三篇知识库文章和三类解决方案详情页。

## 10. 本轮结论

本轮确认：Demo 阶段不需要后台和数据库，也可以通过清晰数据结构、静态路由、SEO metadata、sitemap、robots 和组件化页面，形成一个可被搜索引擎识别、可被 AI 引用、客户能看懂且愿意咨询的专业平台原型。

## 11. 下一轮建议

第一，确认正式域名并替换 `lib/seo.ts` 中的 `siteUrl`。

第二，若内容量扩大，优先接入轻量 CMS 或数据库内容表，而不是继续堆 TypeScript 数据。

第三，若开始做线索转化，应新增咨询表单、线索存储和基本防垃圾提交机制。
