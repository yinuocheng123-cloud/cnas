# 版本记录：v0.43-navigation-minimalization-closure

## 1. 本轮目标

本轮只处理导航，不改站点结构。

核心目标：

- 把“行业方案”导航从双栏说明式 dropdown 收回到真正的产品型轻导航
- 解决 dropdown 过宽、裁切和阅读负担问题
- 保留行业内容资产，但不再放在 hover 导航里阅读

本轮属于：

- 导航收口
- 信息层级修正
- 可用性优化

## 2. 背景与上下文

本轮承接：

- `v0.42-platform-closure-and-recommendation-chain`
- `v0.35-industry-taxonomy-unification`

`v0.42` 为了补平台化推荐链，把行业 taxonomy 的判断短句接进了导航下拉，形成“行业名 + 判断句”的双栏结构。这个方向在平台感上是成立的，但在导航层级上开始越界：

- 用户需要在导航里阅读
- dropdown 变宽
- 小屏和窄浏览器更容易裁切
- 导航从“索引”变成了“内容区”

这和本轮“快速进入而不是导航里阅读”的目标冲突。

## 3. 问题分析

本轮开始前的核心问题有四个：

1. 行业方案 dropdown 太像轻量版 mega menu
2. 右侧说明文本让导航承担了不该承担的教育职责
3. 浏览器宽度稍小就容易出现展示不完整
4. 导航权重上升，开始打扰正文内容

真正的矛盾不是“内容不好”，而是“内容放错位置”。

## 4. 候选方案比较

### 方案 A：继续保留双栏，只缩短文案

优点：

- 改动小
- 行业判断仍然可见

缺点：

- 导航依然承担阅读任务
- 宽度和裁切问题只能缓解，不能根治

结论：

放弃。

### 方案 B：导航改为单列轻菜单，行业判断迁回方案页 Hero

优点：

- 导航职责清晰
- 宽度稳定
- 更符合产品型导航气质
- 内容资产仍然保留，只是迁移位置

缺点：

- 导航本身的信息密度会明显下降
- 用户需要进入页面后再看到判断句

结论：

采用。

## 5. 最终决策

最终采用方案 B，并落实为三件事：

1. 桌面端行业方案 dropdown 改为极简单列
2. 移动端行业方案改为轻量展开列表
3. 行业判断短句从导航迁移到对应方案详情页 Hero

## 6. 具体实现

### `components/Header.tsx`

- 桌面 Header 高度统一为：
  - 移动 `h-14`
  - 桌面 `h-16`
- 一级导航间距统一为 `gap-6`
- 一级导航字号统一为 `text-[15px] font-medium`
- 行业方案 dropdown 改为：
  - `left-1/2`
  - `-translate-x-1/2`
  - `w-[260px]`
  - `max-w-[90vw]`
  - `rounded-2xl`
  - `border`
  - `bg-white/95`
  - `backdrop-blur`
  - `shadow-sm`
- 行业方案菜单项统一为：
  - `px-4 py-3`
  - `text-sm`
  - `leading-6`
- 删除了：
  - 双栏结构
  - 右侧说明区
  - 行业判断短句在导航中的展示

同时：

- 移动端抽屉不再只保留“方案”总入口
- 改成轻量展开的行业方案单列列表
- 不增加描述、不增加二级 hover、不增加复杂层级

### `app/solutions/[slug]/page.tsx`

- 从 `industry-taxonomy` 读取 `judgment`
- 将行业判断短句通过 `HeroSection` 的 `emphasis` 显示在对应行业方案页 Hero

这样做的目的，是把原本错误放在导航里的内容，迁移到更适合承载判断语义的页面首屏。

## 7. 本轮优点

- 导航更像产品平台，而不是企业官网 dropdown
- 行业方案入口一眼能扫完
- 小宽度下更不容易被裁切
- 行业判断内容没有丢失，而是回到了方案页 Hero
- 首页 Hero 下方的行业 pills 继续保留，平台入口层没有受影响

## 8. 本轮缺点与代价

- 导航层的信息密度明显减少，用户在 hover 时无法提前获取行业语义
- 移动端新增了一个轻量展开按钮，虽然简单，但仍然比纯平铺多一步
- 目前案例 dropdown 仍保留四列结构，本轮没有进一步收口它

这些代价是可接受的，因为本轮目标就是让导航“更少、更快、更克制”。

## 9. 验证与结果

本轮完成后执行：

- `npm run typecheck`
- `npm run build`
- `npm run dev`

重点验证：

- dropdown 不裁切
- 行业方案菜单不超宽
- 移动端展开不拥挤
- 方案详情页 Hero 能看到对应行业判断短句

## 10. 本轮结论

本轮最重要的结论是：

导航层应该只负责“快速进入”，不负责“阅读和理解”。

行业判断这种内容，不该消失，但也不该停留在 hover 里。把它迁回行业方案页 Hero 后，信息层级会更自然，导航也会更像真正的产品导航。

## 11. 下一轮建议

1. 如果继续做导航收口，可以考虑同步检查“案例解析” dropdown 是否也需要进一步简化
2. 可以补一次桌面 1366 和手机宽度的真实浏览器人工复核，确认 hover 边界和抽屉节奏
3. 如果后续想进一步极简，可以再评估是否保留部分一级导航 children
