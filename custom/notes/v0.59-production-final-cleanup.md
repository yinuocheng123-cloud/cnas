# 版本记录：v0.59-production-final-cleanup

本轮目标是完成上线前最终收口，不新增业务功能，只处理部署源安全、生产环境变量、Next.js 构建边界和记录沉淀，确保当前项目可以从 GitHub 或部署平台拉取后安全上线试运行。

本轮属于生产上线清理，不做后台重构，不新增数据库，不新增复杂依赖。

## 3. 问题分析

`v0.58` 指出的核心问题是：`data/leads.json` 和 `custom/experiments/dev-image-system.out.log` 已被 Git 跟踪，单靠 `.gitignore` 不会让它们退出仓库；上级目录存在 `C:/Users/Administrator/package-lock.json`，会触发 Next.js workspace root 推断警告；生产环境缺少 `SITE_URL` 时会导致 canonical、Open Graph、sitemap 和 robots 输出本地域名。

本轮判断：这些问题都属于上线前必须收口项，且可以通过最小配置与 Git 索引调整解决，不需要改动线索 API、后台线索页或表单业务逻辑。

## 4. 候选方案比较

方案一：删除本地 `data/leads.json` 和实验日志。

- 优点：本地目录更干净。
- 缺点：会破坏本地兜底线索文件和历史调试现场，不符合本轮要求。
- 结论：放弃。

方案二：只执行 `.gitignore` 忽略规则。

- 优点：改动少。
- 缺点：已被 Git 跟踪的文件仍会继续进入提交。
- 结论：放弃。

方案三：使用 `git rm --cached` 取消跟踪，同时保留本地文件。

- 优点：既保护本地兜底能力，又避免真实线索和日志进入部署源。
- 缺点：Git 状态中表现为删除仓库文件，需要在记录中说明这是“取消跟踪”而不是本地删除。
- 结论：采用。

## 5. 最终决策

采用最小上线清理方案：

- 对 `data/leads.json` 和 `custom/experiments/dev-image-system.out.log` 执行 `git rm --cached`，保留本地文件。
- 在 `.gitignore` 中补充 `data/*.json` 和 `custom/experiments/*.log`。
- 在 `next.config.mjs` 中显式配置 `outputFileTracingRoot` 为当前项目根目录。
- 在 README 中补强 v0.59 生产环境变量说明。
- 在部署构建环境中缺少 `SITE_URL` 时主动失败，避免正式部署输出 localhost 域名。

## 9. 当前是否建议上线试运行

建议上线试运行，但前提是部署平台已经配置真实生产环境变量，尤其是 `SITE_URL`、`ADMIN_KEY` 和至少一个线索 webhook。

如果部署平台未配置 `SITE_URL`，部署构建会主动失败，这是为了避免正式站输出错误 canonical、Open Graph、sitemap 或 robots 域名。

## 10. 正式上线前仍需人工配置项

正式上线前仍需人工在部署平台配置：

- `SITE_URL`：真实正式域名，例如 `https://www.example.com`。
- `ADMIN_KEY`：足够长的随机后台访问 key。
- `LEAD_WEBHOOK_FEISHU`：飞书群机器人 webhook。
- `LEAD_WEBHOOK_WECHAT`：企业微信群机器人 webhook。

`LEAD_WEBHOOK_FEISHU` 和 `LEAD_WEBHOOK_WECHAT` 至少配置一个，否则线索无法稳定外发，只能依赖本地兜底文件。
