# 版本记录：v0.4-cnas-content-platform-restructure

## 1. 本轮目标

本轮目标是把 v0.3 的“杭育 CNAS Demo”调整为更适合长期内容扩展、符合 GEO、TEO、SEO 的“CNAS专业知识与认可解决方案平台”。

目标类型：信息架构重构、内容模型升级、SEO 强化、TEO 转化优化。

## 2. 背景与上下文

本轮承接 `custom/notes/v0.3-seo-data-components.md`。上一轮已经完成 Next.js App Router、TypeScript、Tailwind、本地数据、组件拆分、metadata、sitemap 和 robots。

本轮开始时按规则执行 `git pull --ff-only`，但当前分支仍没有上游跟踪信息，且本地未配置可拉取的 GitHub remote，因此无法同步远端。后续如需严格执行每次 pull，需要先配置远端和 upstream。

## 3. 问题分析

上一轮的页面虽然可访问，但整体仍偏向“杭育服务站”表达。用户本轮明确要求网站不是普通企业官网，而是 CNAS 专业内容平台：主语要从服务商转向企业决策问题、CNAS认可专业判断、实验室能力建设和评审风险。

核心矛盾是：Demo 阶段不接 CMS 和数据库，但仍要让内容结构具备长期扩展能力，并让搜索引擎、AI 和客户都能识别页面价值。

## 4. 候选方案比较

方案一：只替换首页文案。

优点是改动小。缺点是无法解决知识库栏目、分类、标签、FAQ、诊断页和长期扩展问题，因此放弃。

方案二：接入真实 CMS 或数据库后重构内容。

优点是更接近长期内容发布系统。缺点是用户明确本轮不做后台、复杂 CMS 和真实数据库部署，因此不采用。

方案三：继续使用本地 TypeScript 数据，但重构内容模型、栏目路由、聚合页和页面表达。

优点是保持 Demo 简洁，又能验证内容平台的信息架构、SEO/GEO/TEO 表达和后续数据库映射边界。最终选择该方案。

## 5. 最终决策

本轮保留现有技术基础：Next.js App Router、TypeScript、Tailwind、本地数据文件、组件拆分、SEO metadata、sitemap、robots。

同时将网站定位改为“CNAS专业知识与认可解决方案平台”。杭育科技只在页脚、关于平台页和咨询转化区作为服务承接方适度出现。

## 6. 具体实现

扩展 `src/data/articles.ts` 的 Article 类型，新增 `tags`、`keywords`、`seoTitle`、`seoDescription` 字段，并将文章扩展为 6 篇：CNAS是什么、CNAS流程、CNAS费用、CNAS周期、CNAS风险、实验室建设。

新增 `src/data/categories.ts`、`src/data/tags.ts`、`src/data/faqs.ts`，支撑分类、标签和 FAQ 聚合。

重构 `src/data/services.ts`，将服务页改为“CNAS认可落地支持体系”，每项服务包含适合企业、常见问题、支持内容、交付结果和风险提醒。

重构 `src/data/cases.ts`，案例统一为“问题—动作—结果”结构。

重构 `lib/site-data.ts`，更新导航、热门问题入口、首页统计和三类行业方案。

新增或强化路由：`/cnas-basic`、`/cnas-process`、`/cnas-cost`、`/cnas-risk`、`/cnas-lab`、`/cnas-faq`、`/diagnosis`、`/faqs`、`/tags/[tag]`、`/categories/[category]`。

更新首页、知识库、文章页、服务页、案例页、方案页和关于页表达，移除“杭育科技官网式”主语。

更新 `app/sitemap.ts`，纳入新增栏目、文章、分类、标签、方案和静态页面。

## 7. 本轮优点

内容平台定位更明确，首页不再像普通代办官网，而是围绕 CNAS认可、实验室能力建设、体系运行、评审风险和持续改进组织。

GEO 结构更完整：文章包含 H1、直接回答、分类、标签、更新时间、正文、判断清单、FAQ、相关推荐和咨询入口。

TEO 表达更清晰：新增风险诊断页、服务边界、风险提示、判断清单、案例拆解和“如需进一步诊断，可联系杭育科技团队”的咨询承接。

SEO 更完整：动态文章页、分类页、标签页都能生成 metadata；sitemap 和 robots 继续可用。

## 8. 本轮缺点与代价

内容仍由本地 TypeScript 文件维护，适合 Demo 和早期验证，不适合长期非技术人员发布。

分类和标签已建立，但数量仍是初始样例，后续需要真实内容运营补充更多文章。

canonical 仍使用 `https://www.hangyukeji.com` 作为可配置常量，上线前必须确认真实域名。

## 9. 验证与结果

已执行 `npm run typecheck`，结果通过。

已执行 `npm run build`，结果通过。构建输出 49 个静态页面，包含 `/sitemap.xml`、`/robots.txt`、分类聚合、标签聚合、FAQ、诊断页、6 篇知识库文章和 3 个行业方案详情页。

## 10. 本轮结论

本轮确认：在不接后台、不接数据库、不做复杂 CMS 的 Demo 阶段，仍然可以通过清晰内容模型、静态聚合路由、GEO 文章结构、TEO 风险表达和 SEO 基础设施，搭建一个真正像“CNAS专业内容平台”的前台。

## 11. 下一轮建议

第一，确认正式域名并替换 `lib/seo.ts` 中的 `siteUrl`。

第二，继续补充每个栏目下的长尾文章，优先覆盖企业搜索高频问题。

第三，若开始接入内容发布系统，建议先将 `Article`、`Category`、`Tag`、`CaseItem`、`ServiceItem` 映射到 Prisma 模型，再考虑管理后台。
