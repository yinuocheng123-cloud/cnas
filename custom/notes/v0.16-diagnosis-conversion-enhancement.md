# 版本记录：v0.16-diagnosis-conversion-enhancement

## 1. 本轮目标

本轮目标是从“用户看懂内容”继续往前推进到“用户愿意行动”，把诊断页从判断说明页进一步强化成咨询承接入口。

本轮重点有三类：

- 首页首屏文案微调，统一行动语言
- 诊断页改造成更明显的风险驱动转化链路
- 补第二批转化导向文章、FAQ 和标签关系

本轮仍然不新增页面组件，不修改设计系统，不做 UI 风格调整。

## 2. 背景与上下文

本轮承接：

- `custom/notes/v0.15-conversion-content-batch.md`
- `custom/notes/v0.14-content-guide.md`

`v0.15` 已经完成第一批高转化文章、FAQ 与标题规范收口，但诊断页仍以“解释和提示”为主，虽然能帮助用户理解问题，却还不足以把高意图用户自然引到行动阶段。

当前项目定位仍然是 CNAS 专业知识与认可解决方案平台，因此不能通过强营销词或大幅 UI 变化提高转化，而要依赖更精准的问题表达、风险顺序、判断逻辑和行动引导。

## 3. 问题分析

本轮最核心的问题是：已有内容能让用户“觉得有帮助”，但未必能让用户“现在就愿意判断自己该不该做”。

具体表现为：

1. 首页首屏仍偏“先理解路径”，缺少更直接的行动承接语气  
   用户能知道平台讲什么，但未必会立刻点进诊断页。

2. 诊断页虽已强化暂缓启动与返工风险，但链路仍偏说明型  
   之前更像“风险说明页”，不像“做一次前置判断的入口页”。

3. 第一批文章覆盖了费用、周期、误区和资料，但第二批还缺少更强的“返工后果”“错误路径成本”“启动前四点判断”等内容

4. FAQ 虽然已有一定量，但还需要更多面向决策和风险的高意图提问，帮助用户从“查资料”切换到“准备咨询”

## 4. 候选方案比较

方案一：继续只补知识库文章，不动首页和诊断页。

优点是改动最小。缺点是用户读完内容后仍缺少明确的行动落点，转化链路不完整，因此放弃。

方案二：通过新增弹窗、悬浮按钮或新表单组件增强诊断页转化。

优点是表面上更像典型获客页。缺点是会触碰组件结构和 UI 组织方式，也不符合本项目“专业、克制、可信”的风格要求，因此放弃。

方案三：保留现有组件体系，只通过页面内已有组件组合、文案顺序调整和轻量 HTML 表单骨架增强承接。

优点是既能保持最小改动和现有视觉风格，又能把诊断页逻辑改成“风险 → 代入 → 后果 → 判断 → 行动 → 表单”。本轮采用此方案。

## 5. 最终决策

本轮最终选择：

1. 首页首屏标题改成更明确的“讲清楚并避免返工”表达
2. 首页主按钮统一为“开始做一次判断”
3. 诊断页首屏增加更强的风险感提示
4. 诊断页按六段链路重排内容：
   - 风险感首屏
   - 不建议急着启动的场景
   - 为什么会走弯路
   - 启动前先判断
   - 诊断价值
   - 行动与两步式表单
5. 第二批新增 8 篇更强行动导向文章
6. 继续增加高意图 FAQ，并强化标签聚合方向

## 7. 本轮优点

本轮主要带来了以下正向效果：

- 首页从“内容入口”更进一步变成“内容解释 + 行动引导”的入口
- 诊断页不再只是风险说明，而是更接近实际咨询前判断页
- 第二批文章把“返工后果”“成本放大”“先判断再启动”讲得更具体
- FAQ 更像真实决策问题，而不是泛知识补充
- 标签聚合页会自然出现更强的转化主题关联

## 8. 本轮缺点与代价

本轮仍有几项现实限制：

- 诊断页的两步式表单目前是前端承接骨架，没有接入后端收集或真实成功状态
- 因为不新增组件，本轮表单交互保持轻量，重点是表达和承接，不是复杂表单流程
- 新增文章仍以手写 TypeScript 数据维护，内容增长后维护成本会继续上升
- 根目录仍没有真实 `AGENTS.md` 文件，无法把“最新一期路径”回写到仓库内该文件

## 10. 本轮结论

本轮最重要的结论有三点：

1. 对当前项目来说，提升转化率最有效的方式不是更强营销，而是让用户更快看见“如果现在判断错，后面会返工”
2. 诊断页只要把顺序改成风险驱动链路，即使不换组件，也能明显更像咨询入口
3. 第二批文章与 FAQ 的重点不应只是补知识空白，而应补“用户为什么会犹豫、为什么会担心做错、为什么现在应该先判断”这些临门一脚问题

## 11. 下一轮建议

1. 如果要继续增强转化，可优先接入诊断表单真实提交与线索收集逻辑
2. 继续补第三批文章时，可围绕扩项、监督评审、方法确认和内部负责人协同做更强的场景化内容
3. 如果后续继续扩内容，建议把首页热点问题与诊断入口做成可配置排序，方便按阶段切换承接重点
