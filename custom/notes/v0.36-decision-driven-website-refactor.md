# 版本记录：v0.36-decision-driven-website-refactor

## 1. 本轮目标
本轮要把网站从“内容展示页”继续收口为“CNAS 判断平台”。

优先解决三个问题：
- 首页虽然已经做过 mobile-first 优化，但叙事仍偏模块目录，用户需要自己拼接信息。
- 案例与诊断页的语气还偏说明型，不够直接地把“先判断再启动”讲透。
- 知识页、方案页和 Footer 还残留少量“官网型”表达，影响上线时的整体一致性。

本轮属于：
- 内容与结构收口
- 转化链路优化
- 可上线表达统一

- 继续沿用 mobile-first、轻量结构、数据驱动和克制视觉。

## 3. 问题分析
修改前的主要问题有三类：

1. 首页结构还是“模块并列”
- 平台路径、热门问题、内容分类、案例与方案都在，但更像内容导航。
- 用户能看到模块，却不一定能马上感知“为什么现在要先判断”。

2. 案例与诊断缺少结果压力
- 案例更像项目介绍，缺少“原来状态 -> 关键动作 -> 结果变化”的突破感。
- 诊断页虽已具备真实提交链路，但仍有些“填写表单”的后台感，判断入口属性不够强。

3. 局部页面语言不够统一
- 知识页和方案页仍有一定“内容中心 / 方案介绍”语气。
- Footer 虽已简化，但还可以更像产品型收尾，而不是官网尾部信息区。

核心矛盾不是组件不够，而是叙事顺序没有完全切到决策逻辑。

## 4. 候选方案比较
### 方案 A：大幅改首页组件布局
- 核心思路：重做首页模块结构，把路径区、案例区、CTA 区打散重组。
- 优点：可以一次性做出更强的“决策面板”感。
- 缺点：改动范围大，容易破坏 v0.35 刚收口的移动端节奏。
- 风险：组件层牵连多，验证成本高。
- 结论：放弃。本轮目标是上线级收口，不适合做结构性翻修。

### 方案 B：保留结构，重写叙事与文案
- 核心思路：沿用现有组件和 section，只调整顺序、标题、说明、案例语言和 CTA。
- 优点：风险低、收敛快、能直接提升判断感和转化语气。
- 缺点：视觉上不会出现剧烈变化，需要靠文案与节奏取胜。
- 风险：如果改得不够克制，会偏成营销文案。
- 结论：采用。

## 5. 最终决策
最终采用“结构不推翻，叙事重写”的方案。

关键决策：
- 首页改成“问题压力 -> 传统方式失效 -> 结果案例 -> 判断路径 -> 行动入口”。
- 案例统一改为“原来状态 / 关键动作 / 结果变化”。
- 诊断页继续作为核心转化入口，但把语言从“填表”改成“快速获取判断”。
- 知识页与方案页不重做模板，只增强判断句、阅读节奏和 CTA 语气。
- Footer 继续收口，强化 Logo、一句话、CTA、联系信息四件事。

## 7. 本轮优点
- 首页更像“行业判断首页”，而不是内容目录。
- 案例更有结果感，读者更容易理解“为什么别人能少走弯路”。
- 诊断页更自然地承接“先判断再启动”的转化逻辑。
- 页面语言更统一，整体更像同一个产品，而不是多个模块拼接。
- 依旧保持低风险改动，没有破坏 design token、mobile-first 节奏或现有提交流程。

## 8. 本轮缺点与代价
- 本轮主要提升的是叙事和判断感，没有新增更深的交互能力。
- 首页虽然叙事更顺，但仍沿用现有组件装配方式，未来若要进一步提升“产品化”感，可能仍需做一次更完整的结构重整。
- 部分判断感依赖文案质量，后续仍可继续通过真实案例、实际数据和更细的行业分层来增强。

## 10. 本轮结论
- 对当前站点来说，最有效的升级不是加功能，而是把已有内容组织成“先判断再启动”的决策路径。
- 保留现有组件结构的前提下，叙事顺序和语言统一足以显著提升平台感。
- CNAS 站点不能照搬泛增长网站的话术，但可以吸收“问题压力 -> 判断 -> 行动”的表达框架。
