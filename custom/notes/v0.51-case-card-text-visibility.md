# 版本记录：v0.51-case-card-text-visibility

## 1. 本轮目标

本轮目标是修复案例卡片中的两类文字体验问题：

- 标题区域需要压缩为一行，避免多行标题占用过多高度。
- 问题描述区域必须完整显示，不能出现省略号或截断。

## 2. 背景与上下文

本轮承接 `v0.50-empty-card-space-closure`。上一轮已经移除了普通卡片中的空占位和不必要等高约束，但案例卡片仍保留了标题与正文的行数截断逻辑，导致截图中红框内容无法完整阅读。

## 3. 问题分析

案例卡片的问题来自两处：

1. `CaseCard` 中标题使用两行 clamp，标题较长时会占用两行，影响卡片节奏。
2. `CaseCard` 中问题描述使用两行 clamp，长问题会被省略，导致用户无法看清案例问题。

另外，文章详情页和方案详情页的相关案例推荐中也存在 `line-clamp-1`，属于同类问题。

## 4. 候选方案比较

方案一：继续保留标题和问题描述裁切。

- 优点：卡片高度更统一。
- 缺点：用户看不完整案例问题，体验差。
- 结论：放弃。

方案二：缩短标题文案，让标题自然一行；问题描述完整显示。

- 优点：标题更利落，正文信息完整。
- 缺点：部分卡片高度会随问题长度略有差异。
- 结论：采用。

## 5. 最终决策

本轮采用“标题缩短 + 正文完整”的处理：

- 案例标题数据缩短为一行表达。
- `CaseCard` 标题使用一行 `truncate`。
- `CaseCard` 问题描述移除 `WebkitLineClamp`。
- 文章详情页和方案详情页的相关案例问题描述移除 `line-clamp-1`。

## 6. 具体实现

修改文件：

- `components/CaseCard.tsx`
- `src/data/cases.ts`
- `app/knowledge/[slug]/page.tsx`
- `app/solutions/[slug]/page.tsx`

## 7. 本轮优点

- 案例标题更短、更清楚。
- 截图红框中的问题描述可以完整显示。
- 相关案例推荐也不再裁切关键问题文本。
- 保持现有案例卡结构，没有引入新组件或新样式系统。

## 8. 本轮缺点与代价

- 问题描述完整显示后，案例卡片高度可能不完全一致。
- 标题改短后比原先少了一些“从 A 到 B”的叙事感，但更适合卡片入口。

## 9. 验证与结果

本轮已执行：

- `npm run typecheck`：通过。
- `npm run build`：通过，Next.js 成功生成 87 个页面。

重点确认案例卡标题一行显示，问题描述不再被省略。

## 10. 本轮结论

案例卡片的核心价值在于让用户看清“企业原本哪里判断错了”。因此问题描述优先完整展示，标题则应该短而明确，不应为了叙事感牺牲卡片阅读效率。

## 11. 下一轮建议

1. 浏览器复核首页案例区和 `/cases` 页面。
2. 如果卡片高度差异仍然影响观感，优先进一步精简 `problem` 文案，而不是重新加裁切。
