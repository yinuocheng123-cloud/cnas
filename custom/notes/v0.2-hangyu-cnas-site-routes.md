# 版本记录：v0.2-hangyu-cnas-site-routes

## 1. 本轮目标

本轮目标是在 v0.1 技术基线之上，把通用 Demo 内容站推进为“杭育｜CNAS专业知识与解决方案平台”的可访问站点原型。

目标类型：功能补充、内容结构落地、可维护性提升。

## 2. 背景与上下文

本轮承接 `custom/notes/v0.1-nextjs-app-router-baseline.md`。上一轮结论是：页面先消费稳定的本地 TypeScript 数据，Prisma/PostgreSQL 只保留后续接入位置。

本轮开始时再次尝试执行 `git pull --ff-only`，仍因当前分支没有上游跟踪信息且本地无 remote，无法从 GitHub 拉取最新代码。

## 3. 问题分析

用户补充了明确的信息架构：首页、知识库、三篇文章、解决方案、案例、服务和关于页面。核心矛盾从“空仓库建基线”变成“在不接数据库的前提下组织一套可迭代内容模型”。

如果每个页面都硬编码内容，短期可快，但后续改文案、加文章、加方案会重复修改多个页面。若直接引入数据库，又超出 Demo 阶段需求。

## 4. 候选方案比较

方案一：每个页面独立硬编码内容。

优点是实现直观。缺点是重复多，后续新增文章或方案需要改多个页面，容易出现导航、推荐和卡片内容不一致，因此放弃。

方案二：引入 Prisma Client 和数据库表。

优点是更接近生产内容管理。缺点是当前只要求 Prisma/PostgreSQL 预留，数据库接入会引入 `.env`、迁移和生成客户端复杂度，因此本轮不采用。

方案三：用 `lib/site-data.ts` 集中维护内容，页面通过 App Router 读取本地 TS 数据。

优点是延续 v0.1 的轻量策略，并让文章页和方案详情页可以复用数据结构。缺点是内容管理仍需改代码，暂不适合非技术人员维护。最终选择该方案。

## 5. 最终决策

最终采用集中数据文件 + App Router 页面组合。

知识库文章使用 `/knowledge/[slug]` 动态路由生成三篇文章详情。解决方案使用 `/solutions/[slug]` 动态路由生成制造企业、检测机构、食品/材料/医疗相关实验室三类详情。首页、知识库首页、解决方案首页、案例、服务、关于保持独立页面。

## 6. 具体实现

新增 `lib/site-data.ts`，集中维护导航、首页核心入口、知识库文章、解决方案、案例和服务。

新增 `components/SiteHeader.tsx`，统一顶部导航与 Logo。

新增 `components/ConsultationCta.tsx`，统一底部咨询转化入口。

重写 `app/page.tsx`，落地首页首屏、三个核心入口、解决方案区、TEO 信任区、案例区和咨询区。

新增 `app/knowledge/page.tsx` 与 `app/knowledge/[slug]/page.tsx`，落地知识库首页和文章详情页结构。

新增 `app/solutions/page.tsx` 与 `app/solutions/[slug]/page.tsx`，落地解决方案首页和详情页。

新增 `app/cases/page.tsx`、`app/services/page.tsx`、`app/about/page.tsx`，补齐栏目页。

更新 `lib/demo-data.ts` 为兼容导出，避免旧入口残留无效数据。

## 7. 本轮优点

内容结构比 v0.1 更贴近真实业务，路由与用户指定清单一致。

文章页统一包含 H1、50字内直接回答、正文分段、关键判断清单、FAQ、相关推荐和底部咨询入口，后续新增文章只需补数据。

解决方案页统一呈现适合谁、解决什么问题、交付什么结果、客户需要配合什么，并为制造企业方案补充了用户指定的 6 段结构。

## 8. 本轮缺点与代价

当前所有内容仍是代码内本地数据，非技术人员无法直接通过后台维护。

页面样式是 Demo 级别，已保证基础可读性和响应式布局，但还不是精细品牌视觉稿。

解决方案中的检测机构和食品/材料/医疗相关实验室详情为结构化模拟内容，后续若有真实业务材料，应进一步替换。

## 9. 验证与结果

本轮计划在依赖安装后执行 `npm run typecheck` 和 `npm run build`。

若依赖安装或构建失败，需要记录失败原因，并在下一轮优先修正。

## 10. 本轮结论

本轮确认了一个适合 Demo 阶段的内容组织方式：把站点内容集中在 TypeScript 数据层，让页面只负责展示结构。这样既能快速落地路由，也能为未来 Prisma/PostgreSQL 替换数据来源保留清晰边界。

## 11. 下一轮建议

第一，确认是否需要品牌视觉规范，再细化首页和栏目页的视觉层级。

第二，确认是否接入真实表单或 CRM，再把咨询按钮从静态跳转改为表单提交。

第三，确认真实案例和服务边界后，替换当前模拟案例与解决方案文案。
