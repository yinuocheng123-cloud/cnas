# 版本记录：v0.30-navigation-interaction-state

## 1. 本轮目标

本轮目标是统一网站导航栏的交互状态：

1. 未点击时默认显示黑色文字。
2. 鼠标悬停时变为蓝色。
3. 当前页面对应的已选中导航项保持蓝色。

本轮优先级属于：

- 导航交互优化
- 视觉状态一致性
- 最小行为增强

## 2. 背景与上下文

本轮承接以下记录：

- `custom/notes/v0.29-homepage-warning-and-card-alignment.md`

此前首页和导航的视觉已逐步收口，但导航文字状态还不统一：

- `Header` 中默认是偏灰色，悬停后变黑。
- `SiteHeader` 中悬停能变蓝，但默认和选中状态不完整。

用户这轮明确要求导航交互收敛为“默认黑色，悬停或点击选中时蓝色”。

## 3. 问题分析

当前问题主要有两点：

1. 默认态和悬停态不符合最新要求。
2. 当前导航没有根据实际页面路径显示“已选中”状态。

真正的问题不在样式值本身，而在于导航缺少一套统一的状态逻辑。

## 4. 候选方案比较

### 方案一：只改 hover 颜色，不做选中态

优点：

- 改动最小

缺点：

- 用户点击后没有持续反馈
- 无法满足“点击选中时变成蓝色”的要求

放弃原因：只解决了一半交互。

### 方案二：基于当前路径同时处理默认态、悬停态和选中态

优点：

- 能完整满足交互要求
- 逻辑清晰
- 可在 `Header` 和 `SiteHeader` 中统一

缺点：

- 需要把导航组件切为 client component

最终选择原因：改动仍可控，但交互完整。

## 5. 最终决策

本轮最终采用以下方式：

1. 将 `Header` 和 `SiteHeader` 改为 client component。
2. 使用 `usePathname()` 获取当前路径。
3. 以当前路径判断顶级导航是否处于激活状态。
4. 默认文字使用黑色，悬停和激活态使用主蓝色 `text-primary`。

## 6. 具体实现

本轮修改文件如下：

- `components/Header.tsx`
  - 增加 `use client`
  - 接入 `usePathname`
  - 为导航项增加默认态、悬停态、激活态颜色逻辑
  - 同步处理带下拉箭头的颜色状态

- `components/SiteHeader.tsx`
  - 增加 `use client`
  - 接入 `usePathname`
  - 统一导航默认态、悬停态、激活态

## 7. 本轮优点

本轮带来的正向效果：

- 全站导航状态更清楚
- 当前页面所属栏目更容易识别
- 默认态与交互态符合用户要求
- 两套头部导航行为统一

## 8. 本轮缺点与代价

当前方案的已知取舍：

- 导航组件改为 client component，会比纯服务端渲染多一点点前端状态逻辑
- 当前激活判断以顶级路径和子项路径为主，若后续导航层级继续复杂化，可能需要抽出通用判断函数

## 9. 验证与结果

本轮计划执行以下验证：

- `npm run typecheck`
- `npm run build`

验证目标：

- `usePathname` 接入后无类型错误
- 导航组件客户端化不影响构建

## 10. 本轮结论

本轮最重要的结论是：导航的高级感不只来自配色，还来自状态是否明确。默认黑、悬停蓝、当前页保持蓝色，这套规则会明显提升导航的可理解性。

## 11. 下一轮建议

1. 如继续打磨导航，可为当前激活项增加更轻的底边或字重变化，但不建议再加重装饰。
2. 如后续导航结构继续扩展，可把激活判断抽成独立工具函数，避免两处重复。
