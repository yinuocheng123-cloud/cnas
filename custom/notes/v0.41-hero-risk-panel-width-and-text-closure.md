# 版本记录：v0.41-hero-risk-panel-width-and-text-closure

## 1. 本轮目标
本轮继续只处理首页 Hero 右侧风险矩阵，不改首页结构。

核心目标：
- 让右侧四个文本框和左侧 Hero 顶边更稳定对齐
- 让右侧文本框占比再大一些
- 让卡片里的文字尽量保持单行
- 移除裁切限制，保证所有文字都完整显示

本轮属于：
- 首页首屏细节收口
- 风险矩阵宽度调整
- 文本显示策略修正

## 2. 背景与上下文
本轮承接：
- `custom/notes/v0.40-hero-risk-panel-final-alignment.md`
- `custom/notes/v0.39-risk-card-alignment-closure.md`

延续结论：
- `v0.40` 已经把首屏主辅关系拉开，右侧不再像第二组 Hero
- 但实际观感里，右侧卡片仍然偏窄，导致标题和说明换行过早，视觉上显得挤

## 3. 问题分析
本轮开始前的具体问题有三点：

1. 右侧栏宽度偏保守
- 虽然之前为了降级右栏，已经把宽度收窄
- 但现在造成了卡片中文字过早断行

2. 文本被两行截断策略限制
- 上一轮为了统一节奏，标题和说明都做了两行截断
- 这虽然整齐，但和当前“所有文字内容都要显示出来”的要求冲突

3. 右侧容器和提示条的可用宽度不足
- 提示条与卡片都还有再放宽的空间
- 当前更像是“信息被挤压”，而不是“克制”

## 4. 候选方案比较
### 方案 A：保持当前宽度，只继续缩字体
- 优点：改动小
- 缺点：文字虽然可能少一点换行，但可读性会继续下降
- 结论：放弃

### 方案 B：增加右栏宽度，移除截断，保留当前结构
- 优点：最符合这轮目标，能同时解决对齐、占比和文字完整显示
- 缺点：右栏会比上一轮稍大，但仍在辅助区范围内
- 结论：采用

## 5. 最终决策
最终采用以下方式：

1. 将 Hero 右栏桌面宽度从 `328px` 放大到 `440px`
2. 保留 2×2 结构，不改首页首屏布局
3. 去掉风险卡片标题与正文的两行截断
4. 轻微缩短卡片最小高度，避免放宽后显得过空
5. 保持标题 `15px`、正文 `text-sm`，让文案尽量单行显示，但在需要换行时也完整呈现

## 6. 具体实现
### `components/HeroSection.tsx`
- 桌面端右栏宽度调整为 `440px`
- 风险提示条的横向内边距略放宽，改善单行容纳能力

### `components/RiskEntryCard.tsx`
- 卡片最小高度从较高值微调到更紧凑的 `128px / 132px`
- 移除标题和正文的 line clamp 样式
- 保持统一字号与行高，让文字尽量单行，但不再裁切

### `app/page.tsx`
- 右侧风险矩阵桌面端 gap 略增，避免放宽后卡片彼此过挤

## 7. 本轮优点
- 右侧文本框和左侧 Hero 更容易形成稳定对齐关系
- 卡片宽度增加后，标题更容易单行显示
- 不再丢失文字内容，和用户当前要求一致
- 不新增结构，不影响首页其余模块

## 8. 本轮缺点与代价
- 右栏比上一轮更宽，辅助区存在感会略有回升
- 如果后续文案再继续变长，仍有可能重新出现多行情况
- 当前策略是“完整显示优先”，会略微放宽之前的统一高度控制

## 9. 验证与结果
本轮计划执行：
- `npm run typecheck`
- `npm run build`
- `npm run dev`

重点检查：
- 首页是否 200
- 右侧四卡片是否更接近单行展示
- 所有文字是否完整显示
- 左右顶边对齐是否仍稳定

## 10. 本轮结论
- 对当前这组风险卡片来说，宽度比继续缩字号更有效
- 当要求“所有文字都必须显示”时，截断策略就应该退场
- 这轮更适合把右栏理解为“可完整阅读的辅助判断区”，而不是纯装饰矩阵

## 11. 下一轮建议
1. 用实际浏览器看一次桌面端首屏，确认右栏是否已经达到“尽量单行”的效果
2. 如果还需微调，优先再调文案长度和栏宽，不要先动左侧 Hero
3. 后续如继续固定高度，可考虑只限制标题行高，不再限制正文显示
