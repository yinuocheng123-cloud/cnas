# 版本记录：v0.26-homepage-three-column-gap-tightening

## 1. 本轮目标

本轮目标是把首页“平台路径”下方三栏内容板块之间的左右间距收紧约 30%，让整体布局更紧凑协调，同时保持板块内部文字大小、排版和卡片结构不变。

本轮优先级属于：

- 信息密度优化
- 首页排版收口
- 最小改动调整

## 2. 背景与上下文

本轮承接以下记录：

- `custom/notes/v0.25-case-dropdown-four-columns.md`
- `custom/notes/v0.20-homepage-spacing-tightening.md`

此前首页在“平台路径”下方已经形成稳定的三栏内容结构，但这些板块横向仍统一使用 `gap-4`，在当前更克制的首页方向下，栏与栏之间略显松散。

用户这轮要求非常明确：

- 只调三栏板块之间的左右间距
- 不改组件结构
- 不改文字大小
- 不改板块内部排版

## 3. 问题分析

当前问题不是内容不够，也不是卡片内部太松，而是三栏板块之间的横向留白略大，导致：

1. 页面在“平台路径”以下的内容段落看起来偏松。
2. 三栏之间的视觉联系稍弱，整体感不够紧。
3. 如果直接压缩卡片内部 padding，会破坏既有排版，因此不适合动内部结构。

核心矛盾是：要提升整体紧凑感，但不能通过改卡片内容密度来实现。

## 4. 候选方案比较

### 方案一：直接把所有 `gap-4` 改成更小的统一 gap

优点：

- 修改简单
- 一次到位

缺点：

- 会同时影响纵向间距
- 容易让卡片上下之间也变挤

放弃原因：本轮目标只针对左右间距，不适合连带压缩纵向节奏。

### 方案二：拆分横向与纵向间距，只收紧 `md` 以上的横向 gap

优点：

- 能精准命中“三栏左右间距”目标
- 保留移动端和纵向阅读节奏
- 不影响卡片内部布局

缺点：

- 类名会比原来稍长

最终选择原因：最符合用户要求，也最符合最小改动原则。

## 5. 最终决策

本轮最终采用以下方式：

1. 保留三栏板块原有 `mt-6`、`md:grid-cols-3` 和卡片内部实现。
2. 将原来的统一 `gap-4` 拆分为：
   - `gap-y-4`
   - `md:gap-x-3`
3. 只在桌面三栏布局下收紧横向距离，纵向不动。

这样可以在不碰内容排版的前提下，让整体观感更紧凑。

## 6. 具体实现

本轮修改文件如下：

- `app/page.tsx`
  - 调整“热门问题入口”三栏 grid 的横向 gap
  - 调整“内容分类入口”三栏 grid 的横向 gap
  - 调整“行业方案入口”三栏 grid 的横向 gap
  - 调整“案例解析”三栏 grid 的横向 gap

## 7. 本轮优点

本轮带来的改善：

- 平台路径下方三栏区块更紧凑
- 卡片内部版式完全保持不变
- 移动端阅读节奏未受影响
- 修改集中在首页单文件，风险低

## 8. 本轮缺点与代价

当前方案的已知取舍：

- 横向收紧是近似 30% 的视觉调整，不是数学上的精确 30%
- 这次只处理首页三栏区块，其他页面若也有类似需求，后续仍需单独判断
- 类名从统一 `gap-4` 变成横纵拆分，可读性略低于原先

## 9. 验证与结果

本轮计划执行以下验证：

- `npm run typecheck`
- `npm run build`

验证目标：

- 首页 JSX 改动无类型错误
- 三栏区块类名调整不影响生产构建

## 10. 本轮结论

本轮最重要的结论是：首页紧凑感问题主要来自板块之间的横向留白，而不是卡片内部密度。因此，优先收紧三栏 grid 的横向 gap，比修改卡片内部 padding 更稳妥。

## 11. 下一轮建议

1. 如继续做首页排版收口，可再检查 Hero 下沿与“平台路径”上沿的衔接密度。
2. 如后续多个页面出现相同三栏收紧需求，可考虑抽成统一栅格类名。
3. 若用户还想进一步收紧，可先做首页可视化复核，再决定是否继续压缩到更小间距。
