# 版本记录：v0.28-footer-gap-tightening

## 1. 本轮目标

本轮目标是收紧首页底部 `CtaBlock` 与 `Footer` 之间的深色空白带，让它不再显得过宽，只保留一条更克制的过渡区域。

本轮优先级属于：

- 首页排版收口
- 底部区块密度优化
- 最小样式调整

## 2. 背景与上下文

本轮承接以下记录：

- `custom/notes/v0.27-homepage-results-matrix.md`
- `custom/notes/v0.26-homepage-three-column-gap-tightening.md`

此前首页已经逐步向更紧凑、更像判断工具的平台方向收口，但底部咨询区和 Footer 仍然连续使用深色背景，并各自带有较大的上下 padding，拼接后会形成一条偏宽的深色空带。

用户本轮的直接反馈是“太宽了”，希望只保留很薄的一段过渡。

## 3. 问题分析

当前问题不在内容过多，而在于两个相邻深色区块之间的视觉断层过大：

1. `CtaBlock` 自身底部 padding 偏大。
2. `Footer` 顶部 padding 也偏大。
3. 两者背景同色，叠加后更容易把中间空带看成“多出来的一段高度”。

核心矛盾是：需要保留模块分隔感，但不能再让分隔依赖大块留白。

## 4. 候选方案比较

### 方案一：只减少一个区块的 padding

优点：

- 改动更少

缺点：

- 另一侧仍会保留较大空白
- 拼接感不稳定

放弃原因：只能缓解一半问题。

### 方案二：同时收紧上下 padding，并用细分隔线接管层次

优点：

- 能直接把大空带压缩成薄过渡
- 保留层次，不会显得硬切
- 不影响文案和按钮结构

缺点：

- 需要同时改两个组件

最终选择原因：最符合用户“就留红色宽度”的意图。

## 5. 最终决策

本轮最终采用以下方式：

1. 收紧 `CtaBlock` 底部 padding。
2. 收紧 `Footer` 顶部 padding。
3. 在 `Footer` 顶部补一条细分隔线，用边界替代大留白。

## 6. 具体实现

本轮修改文件如下：

- `components/CtaBlock.tsx`
  - 将底部 padding 从原来的大块留白收紧为更薄的过渡

- `components/Footer.tsx`
  - 将顶部 padding 收紧
  - 增加顶部细分隔线，保留层次感

## 7. 本轮优点

本轮带来的正向效果：

- 底部深色区块衔接更紧凑
- CTA 与 Footer 仍然分区清晰
- 不改文案、不改按钮、不改结构
- 整体观感更克制

## 8. 本轮缺点与代价

当前方案的已知取舍：

- 底部呼吸感会比原来更弱一些
- 当前只处理首页底部拼接，其他页面若有类似相邻深色区块，后续可能也要统一判断

## 9. 验证与结果

本轮计划执行以下验证：

- `npm run typecheck`
- `npm run build`

验证目标：

- 底部组件样式调整不引入类型问题
- 构建结果保持稳定

## 10. 本轮结论

本轮最重要的结论是：对于同色背景的相邻区块，层次感更适合通过细分隔线和较小留白实现，而不是依赖大面积空带。

## 11. 下一轮建议

1. 如继续收口首页，可再检查 `CtaBlock` 按钮与正文在宽屏下的横向距离是否还偏松。
2. 如用户希望更像工具平台，可继续压缩 Footer 的描述信息量。
