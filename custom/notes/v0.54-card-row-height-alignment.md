# 版本记录：v0.54-card-row-height-alignment

## 1. 本轮目标

本轮目标是修复成组卡片同一行高度不一致的问题，让方案卡、路径入口卡和分类卡在桌面端更整齐。

用户截图指出：同一组卡片底部不齐，按钮或卡片底边位置有明显错位。本轮属于视觉一致性收口，不新增功能，不改变页面结构，不改内容数据。

## 2. 背景与上下文

本轮承接：

- `custom/notes/v0.50-empty-card-space-closure.md`
- `custom/notes/v0.53-case-card-button-alignment.md`

`v0.50` 为了消除卡片内部空白，偏向自然高度；`v0.53` 已经确认案例卡因为有 CTA，需要局部恢复 `h-full + mt-auto`。本轮继续沿用“只在需要整齐排布的成组卡片中恢复等高”的策略，不回退为全站所有卡片强制等高。

## 3. 问题分析

截图中的问题主要来自两类区域：

1. 方案卡：同一行不同卡片文字长度不同，按钮没有贴底，导致按钮和卡片底部不齐。
2. 路径入口卡：父级网格使用 `items-start`，卡片按自然高度显示，短文案卡片明显更矮。

核心矛盾是：内容型卡片需要避免大面积空白，但成组入口卡也需要保持行高统一，否则页面显得不规整。

## 4. 候选方案比较

方案一：全局恢复 `.card-link h-full`。

- 优点：所有卡片都会等高。
- 缺点：会回退 `v0.50` 的全站空白收口成果，短内容卡片可能再次出现大空白。
- 结论：放弃。

方案二：只在方案卡、分类卡和首页路径入口等“成组入口卡”中启用等高。

- 优点：解决截图问题，影响范围可控；不改变文章列表等自然阅读区。
- 缺点：短卡片底部会出现少量留白。
- 结论：采用。

## 5. 最终决策

采用局部等高策略：

- `SolutionCard` 使用 `h-full`，按钮容器使用 `mt-auto`。
- `CategoryCard` 使用 `h-full`。
- 首页路径入口和热门问题入口使用 `h-full`。
- 相关网格移除 `items-start`，恢复 CSS grid 默认 stretch。
- 保留移动端单列区域和文章列表的自然高度策略。

具体改动：

- 方案卡按钮区域增加 `mt-auto`，确保按钮贴近卡片底部。
- 分类卡外层增加 `h-full`。
- 首页路径入口和热门问题卡增加 `h-full`。
- 首页路径、热门问题、分类、方案列表、方案详情相关卡片网格移除 `items-start`。

## 7. 本轮优点

- 同一行方案卡高度一致，按钮位置更规整。
- 首页路径入口卡底边一致，不再出现单张卡明显偏短。
- 知识库分类、方案列表、方案详情相关卡片也采用同类等高规则。
- 没有改动文章列表、移动端单列区和全局 `.card-link` token，避免过度扩散。

## 8. 本轮缺点与代价

- 短内容卡片底部会出现少量弹性留白，这是等高排布的必要代价。
- 如果未来某些卡片文案差异特别大，行高仍会被最长卡片决定。
- 本轮没有重新设计卡片文案长度，只处理布局规则。

## 10. 本轮结论

成组入口卡和普通内容阅读卡应使用不同策略。入口卡更强调整齐和扫描效率，可以局部等高；文章列表等阅读型内容仍保持自然高度，避免重新产生过多空白。

## 11. 下一轮建议

1. 浏览器复核首页路径入口区和行业方案区。
2. 如仍有明显留白，优先精简文案长度，而不是继续增加固定高度。
3. 后续如果类似问题继续出现，可考虑抽出统一的 `equal-height-card-grid` 约定，但当前不需要新增抽象。
