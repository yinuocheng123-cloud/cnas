# 版本记录：v0.23-mobile-first-refinement

## 1. 本轮目标

本轮目标是正式启动整站移动端适配，把当前网站从“桌面端成立”推进到“手机端也能正式给客户看”的状态。

本轮不新增页面、不推翻现有信息结构，只做 mobile-first 收口，覆盖：

- 首页
- 导航
- Hero
- 卡片与列表
- 表单
- 文章页 / 方案页 / FAQ
- Footer

## 2. 背景与上下文

本轮承接以下记录：

- `custom/notes/v0.31-navigation-ice-blue-state.md`
- `custom/notes/v0.20-homepage-spacing-tightening.md`
- `custom/notes/v0.16-diagnosis-conversion-enhancement.md`

此前站点已经完成了内容增强、首页信息架构收口、诊断承接链路与导航状态统一，但这些优化主要建立在桌面端观感上。移动端虽然能访问，但仍存在：

- 首屏偏高
- 导航仍偏桌面逻辑
- section 留白过松
- 详情页阅读宽度和节奏不够克制
- 诊断表单触控感不够强

因此本轮重点不是“补功能”，而是把已有内容和结构变成真正适合手机的产品体验。

## 3. 问题分析

本轮开始前的核心问题有五类：

1. 首页在手机端仍偏“放大缩小后的桌面页面”
2. 导航缺少真正的移动端模式
3. 卡片与 section 的手机端密度偏松，一屏信息太少
4. 详情页标题、段落与相关推荐在手机端的阅读节奏不够紧凑
5. 诊断页虽然功能完整，但表单和行动区在手机端还不够像真实咨询入口

真正的矛盾不是页面数量太多，而是很多模块还没切换成 mobile-first 的节奏。

## 4. 候选方案比较

### 方案一：只在现有桌面结构上补少量 `sm:` / `md:` 样式

优点：

- 改动少

缺点：

- 很容易变成“能缩小，但不像产品”
- 导航、首屏和表单体验改善有限

放弃原因：不够解决本轮目标。

### 方案二：在保留现有结构的前提下，系统性收口移动端字号、间距、导航和表单

优点：

- 符合 mobile-first 原则
- 不需要推翻信息架构
- 可以把首页、详情页和诊断页一起拉到统一节奏

缺点：

- 需要跨多个通用组件同步调整

最终选择原因：最符合当前阶段，也最稳。

## 5. 最终决策

本轮最终采用以下方式：

1. 全局降低手机端标题等级，提升正文行高
2. 收紧手机端 `site-shell`、`section-space`、`card`、`card-link`
3. 为按钮统一最小触控高度 `44px+`
4. 将 Header / SiteHeader 增加移动端抽屉式菜单
5. 首页各 section、Hero、结果矩阵区和 CTA 在手机端整体收紧
6. 诊断页表单按钮、间距、字段高度按移动端重排
7. 文章页 / 方案页 / FAQ / 列表页同步收紧阅读节奏

## 6. 具体实现

本轮修改文件如下：

- `tailwind.config.ts`
  - 将 `display`、`title` 手机端字阶整体降低一级
  - 将 `body` 行高提升到更适合手机阅读的节奏

- `app/globals.css`
  - `site-shell` 手机端横向留白从 `px-6` 收紧到 `px-4`
  - `section-space` 从 `py-8` 收紧到 `py-6`
  - `card` / `card-link` 手机端 padding 从 `24px` 收紧到 `16px`
  - `btn-primary` / `btn-secondary` 增加统一最小触控高度

- `components/Header.tsx`
  - 增加移动端菜单按钮
  - 移动端改为简洁抽屉式纵向菜单
  - 菜单仅保留“知识库 / 流程 / 方案 / 案例 / FAQ / 诊断”
  - Logo 增加 `sizes`

- `components/SiteHeader.tsx`
  - 同步移动端抽屉导航和 Logo `sizes`

- `components/HeroSection.tsx`
  - 首屏纵向 gap、上下 padding 收紧
  - 手机端标题宽度和字号下调
  - CTA 在手机端改为纵向全宽优先
  - 风险提示行高和阅读宽度优化

- `components/ProcessSteps.tsx`
  - 手机端改为更紧凑的单列卡片
  - 去掉手机端强制最小高度

- `components/RiskNotice.tsx`
  - 手机端行高增加

- `components/ChecklistBlock.tsx`
  - 手机端行高增加

- `components/LeadCaptureForm.tsx`
  - 行动区、两步式表单、提交按钮、字段高度改成更明确的移动端节奏
  - 提交按钮在手机端全宽

- `components/CtaBlock.tsx`
  - 手机端上下留白和按钮宽度收紧

- `components/Footer.tsx`
  - 手机端底部留白再收一档

- `components/FaqLanding.tsx`
  - FAQ 列表在手机端减少 section 高度与卡片间距

- `app/page.tsx`
  - Hero 以下各 section 的 `pt` / `pb` / `gap` 全部收紧
  - 平台路径和首页各内容区在手机端保持单列与更小间距
  - 长句说明不再使用桌面导向的强一行约束
  - 结果矩阵和 CTA 在手机端改为更紧凑的单列节奏

- `app/diagnosis/page.tsx`
  - 诊断页各段之间的手机端留白收紧

- `app/knowledge/page.tsx`
  - 分类、标签、文章列表区的手机端间距收紧

- `app/knowledge/[slug]/page.tsx`
  - 标题字号降低一级
  - 正文行高增加
  - 相关推荐区保持手机端单列

- `app/solutions/page.tsx`
  - 方案列表手机端更紧凑

- `app/solutions/[slug]/page.tsx`
  - 手机端标题、正文、步骤区与底部 checklist 节奏收紧

## 7. 本轮优点

本轮带来的正向效果：

- 手机端首页不再像“缩小版官网”
- 导航更接近工具型平台，而不是桌面菜单强行换行
- 一屏可见信息更多，滚动节奏更连续
- 表单更像真实可提交入口
- 详情页阅读舒适度明显提升

## 8. 本轮缺点与代价

当前方案的已知取舍：

- 这轮为了快速拉齐手机端体验，改动覆盖面较广
- 移动端抽屉菜单目前仍是轻量实现，没有再加更复杂的层级过渡
- `#4ECDC4` 导航状态色继续沿用在新移动菜单中，尚未抽成全局 token
- `custom/notes` 的版本号按用户要求命名为 `v0.23`，与仓库既有历史版本序号不连续，这是本轮有意接受的命名兼容

## 9. 验证与结果

本轮计划执行以下验证：

- `npm run typecheck`
- `npm run build`
- `npm run dev`
- 检查：
  - `/`
  - `/knowledge`
  - `/solutions`
  - `/diagnosis`
  - `/faqs`

验证目标：

- 手机宽度下无横向滚动
- 无超宽内容和大面积空白
- 导航、首页、详情页和诊断页都能稳定访问

## 10. 本轮结论

本轮最重要的结论是：移动端适配不是把桌面页面“压小”，而是把信息密度、导航模式、标题重量和表单触控感全部重新收口。只有这样，网站在手机上才像一个专业判断平台，而不是宣传页。

## 11. 下一轮建议

1. 用真实手机宽度继续复核首页 Hero 和诊断表单是否还需要再压一档
2. 如果后续继续做移动端收口，可考虑把更多交互色和 spacing 提炼为显式 token
3. 若准备上线投流，下一轮可直接进入“移动端截图复核 + 最终上线检查”阶段
