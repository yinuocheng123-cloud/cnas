# 版本记录：v0.33-launch-ready-mobile-closure

## 1. 本轮目标

本轮目标是把现有站点进一步收口到“可上线展示版本”，重点不是新增功能，而是把移动端体验、首页转化节奏、图片信任感、CTA 触达和详情页阅读体验压实到可以正式给客户看的状态。

本轮属于：

- 可维护性提升
- 上线质感收口
- 转化路径优化

## 2. 背景与上下文

本轮承接以下记录：

- `custom/notes/v0.32-real-scene-image-system.md`
- `custom/notes/v0.31-navigation-ice-blue-state.md`
- `custom/notes/v0.23-mobile-first-refinement.md`
- `custom/notes/v0.20-homepage-spacing-tightening.md`
- `custom/notes/v0.18-webhook-lead-notification.md`
- `custom/notes/v0.16-diagnosis-conversion-enhancement.md`
- `custom/notes/v0.13-design-token-system.md`

修改前，站点已经具备：

- 内容驱动的页面结构
- 真实场景图片系统
- 诊断表单提交链路
- 基本的移动端适配

但仍有几个明显问题：

- 首页 Hero 在手机端仍偏松，首屏判断与 CTA 触达不够直接
- section 之间节奏还不够连续，仍有“PPT 分段感”
- CTA 文案不统一，部分仍带“进入/查看详情”这类弱动作表达
- 知识详情页和方案详情页在手机端阅读宽度与段落节奏还不够收敛
- Footer 仍偏传统页脚，不够像产品型平台

## 3. 问题分析

表面问题看起来是“间距、按钮、图片和移动端要再调一轮”，但核心矛盾其实是：

1. 现有站点已经有足够多的信息，但还没有把“判断平台”的节奏压到足够利落
2. 如果继续加内容或加组件，反而会把本来已经形成的专业感打散
3. 当前最需要的是减少噪音、统一动作语言、让用户更快进入判断和咨询

因此，本轮不应该重构，而应该做“最小改动的节奏优化”。

## 4. 候选方案比较

### 方案一：继续局部加样式，尽量不重写页面

核心思路：
只改少量 class，尽量不动页面主体结构。

优点：

- 改动更少
- 风险较低

缺点：

- 当前多处页面文案、间距和 CTA 逻辑已经分散，单点补丁会继续累积不一致
- 很难一次性把 Hero、CTA、Footer、详情页阅读节奏统一下来

放弃原因：
不利于本轮“上线前统一收口”的目标。

### 方案二：在现有结构不变前提下，重写关键页面文件中的文案与响应式 class

核心思路：
保留组件体系和数据驱动结构，只重写关键文件的页面骨架和 class 组织方式。

优点：

- 不引入新组件
- 可以一次性统一 Hero、CTA、阅读宽度、Footer 和移动端节奏
- 仍然属于最小边界内的增量修改

缺点：

- 关键页面文件改动面看起来较大
- 需要重新验证 build 和移动端展示

最终选择原因：
这是在不做架构调整前提下，最快达到“上线可展示状态”的方案。

## 5. 最终决策

本轮最终采用方案二，原则如下：

1. 不新增复杂组件，不重构数据结构
2. 保留现有图片系统，继续使用 `next/image`
3. 统一按钮动作语言为“开始诊断 / 获取方案 / 查看案例 / 立即咨询”
4. 把移动端首屏高度、section 节奏、详情页阅读宽度和 Footer 收口到一致风格

## 7. 本轮优点

本轮方案的主要优点：

- 移动端首页首屏更直接，CTA 更容易触达
- section 节奏更连续，明显减少“断层感”
- CTA 文案统一后，整站动作更明确
- 图片继续作为辅助信任，而不是抢占视觉主导
- 详情页阅读宽度更收敛，手机端阅读压力更小
- Footer 更像产品页脚，而不是企业官网尾部信息堆叠

## 8. 本轮缺点与代价

本轮也有明确代价：

- 关键页面文件进行了重写式整理，虽然不涉及结构重构，但需要更仔细验证
- 一部分原先较长的说明被压缩，信息密度更高，对文案准确性要求更高
- 诊断页 CTA 更聚焦后，后续如果要继续做 A/B 测试，可能还需要再拆分入口位置

当前暂时接受这些代价，因为本轮优先级是“先让站点整体上线可展示”。

## 10. 本轮结论

本轮最重要的结论是：

这个项目已经不需要继续加结构，而是需要把已有结构的节奏、触达路径和阅读体验打磨得更像一个“专业判断平台”。

被继续验证并沿用的旧判断：

- 不做企业官网风
- 不靠大视觉或重动画建立价值感
- 真实图片应服务于信任，而不是服务于宣传
- mobile-first 不是缩小桌面，而是重排信息密度

## 11. 下一轮建议

1. 完成移动端截图级复核，重点看 Hero 高度、CTA 首屏触达和 Footer 是否仍显拖沓
2. 如果要继续收口，优先检查知识列表页和 FAQ 页的移动端密度是否与首页一致
3. 如果准备正式投流，可进一步补一轮真实联系方式、咨询时效和运营说明
