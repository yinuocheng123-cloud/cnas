# 版本记录：v0.19-homepage-density-refinement

## 1. 本轮目标

本轮目标是只做“排版收敛 + 信息密度优化”，不增加组件、不改页面逻辑结构，只把首页收成更克制、更稳定、更像专业判断型平台的状态。

本轮优先级属于：

- 视觉收口
- 可读性提升
- 设计系统延续

## 2. 背景与上下文

本轮承接以下记录：

- `custom/notes/v0.18-webhook-lead-notification.md`
- `custom/notes/v0.13-design-token-system.md`

`v0.13` 已经建立了字体、颜色、间距、卡片和按钮的基础 token 体系，但首页在持续补内容后，信息密度开始偏松：  
Hero 标题存在视觉压迫感，路径区留白偏大，说明性标签过多，导致页面更像“解释很多的企业官网”，而不是“专业判断型平台”。

本轮不做功能扩展，核心是用更统一的字阶、间距和对齐关系，把信息层级重新拉开。

当前仓库中依然没有实际存在的根目录 `AGENTS.md` 文件，因此无法把“最新一期路径”回写到仓库内该文件，只能在 notes 中显式保留本轮记录。

## 3. 问题分析

本轮开始前，首页的主要问题不是内容错，而是信息组织显得偏松：

1. Hero 视觉压迫感偏强  
   标题尺寸和行距都比较激进，容易产生“喊口号”的感觉，不够专业克制。

2. 首屏左右区块不够平衡  
   风险提示条单独占一行，和右侧三张卡片不在同一视觉区域，导致左侧更像连续堆叠，右侧更像独立模块。

3. “平台路径”区解释性噪音偏多  
   `流量入口 / 强需求入口 / 成交入口` 这类标签对首次理解帮助有限，反而占据了卡片的第一视觉层。

4. 间距有统一基础，但首页局部仍偏松  
   尤其是 Hero 之后到路径区之间，以及路径卡片与说明之间的留白，影响了页面节奏。

核心矛盾不是“视觉不够丰富”，而是“信息已经足够，只需要更克制地排出来”。

## 4. 候选方案比较

### 方案一：增加装饰感与区块区分

核心思路：通过更明显的背景块、边框、徽标和卡片标签来强化分区。

优点：

- 视觉变化明显
- 容易让页面“看起来做了很多”

缺点：

- 更容易滑向企业官网感
- 会削弱当前项目“判断型平台”的克制气质
- 与本轮“信息更少，但更清晰”的目标相反

最终放弃原因：本轮不需要更强设计，而是需要更少干扰。

### 方案二：收紧排版密度、删掉解释性冗余、统一 token 节奏

核心思路：保留现有结构，只通过标题尺寸、段落密度、风险提示位置、卡片间距和标签删除来优化层级。

优点：

- 改动面小
- 风格更统一
- 更符合专业平台的克制感
- 不需要新增任何组件或复杂结构

缺点：

- 变化比加装饰更隐性，需要靠整体观感才能体现价值

最终选择原因：最符合本轮目标。

## 5. 最终决策

本轮最终采用以下策略：

1. 收紧全局 `display / title / section-space`，让首页第一屏和区块间距整体更稳
2. 首页 Hero 改成三行标题，但降低视觉压迫感
3. 风险提示条移入右侧卡片视觉区域，与三张统计卡片顶部对齐
4. 删除“平台路径”卡片顶部的入口标签，只保留标题和摘要
5. 收紧路径区留白和卡片之间的节奏
6. 把一条过长的说明句收成更像“判断结论”的一行表达

## 6. 具体实现

本轮主要修改如下：

- `tailwind.config.ts`
  - 调整 `display` 字阶到更克制的尺寸与行高
  - 调整 `title` 字阶，减少标题层级的膨胀感

- `app/globals.css`
  - 新增基础 spacing 变量，明确 8px 递进节奏
  - `section-space` 从更松的区块间距收紧到 `40 / 48` 主节奏
  - `card-link` 改为 `flex + h-full`，让路径卡片自然等高
  - `hero-subline` 改为与主标题同层，不再额外缩小

- `components/HeroSection.tsx`
  - `balanced` 变体改为左右顶部对齐
  - 收紧 Hero 标题行高与整体宽度
  - 风险提示条从左侧连续堆叠区移入右侧区域
  - 风险提示条 padding 和字号保持辅助层级，不再独占首屏主体

- `components/SectionTitle.tsx`
  - 增加 `descriptionClassName`，让首页路径区可单独控制说明行宽

- `app/page.tsx`
  - 首页 Hero 标题改为三行结构：
    - `企业做CNAS认可前`
    - `先把关键路径想清楚`
    - `再去做实验室能力建设`
  - Hero 说明收成一句判断型说明，降低信息量
  - 路径区上边距改为更紧的 `40 / 48`
  - 路径区说明改为一行主说明
  - 删除五张路径卡片顶部的 `流量入口 / 强需求入口 / ...` 标签
  - 风险说明长句中的“稳定支撑检测”删除，改为更干净的一行判断句

## 7. 本轮优点

本轮带来的主要收益有：

- 首页首屏更像专业判断入口，而不是营销型大标题
- 左右区块更平衡，首屏不再出现明显“一高一低”的割裂感
- 路径区噪音减少后，用户能更快理解每张卡片的用途
- 全局 spacing 与字阶更稳，页面整体会显得更“贵”而不是更“满”

## 8. 本轮缺点与代价

本轮也有几个现实取舍：

- 这是排版收紧，不是视觉重做，因此变化主要体现在整体观感，而不是明显的新设计
- 路径区说明虽然尽量压成一行，但仍会根据屏幕宽度在较小视口自然换行
- 为了坚持最小改动，没有去逐页重排所有页面，只是把全局 token 稍微收紧，并重点作用在首页

这些取舍是有意接受的，因为本轮目标不是“做得更花”，而是“做得更稳”。

## 10. 本轮结论

本轮最重要的结论有三点：

1. 对当前项目来说，“高级感”更多来自密度控制和层级清晰，而不是更多设计元素
2. 删除解释型噪音，往往比新增视觉装饰更能提升专业平台气质
3. `v0.13` 建立的 token 体系仍然有效，本轮只需要收紧，而不是推翻重建

## 11. 下一轮建议

1. 如果继续收口视觉，优先检查 `/knowledge`、`/solutions`、`/services` 的区块密度是否也需要同步微调
2. 如果要进一步提升“看起来更贵”的感觉，建议下一轮先做浏览器截图级检查，再决定是否继续压缩局部留白
3. 保持“删解释、保判断”的方向，不要再把首页拉回企业官网式的入口堆叠
