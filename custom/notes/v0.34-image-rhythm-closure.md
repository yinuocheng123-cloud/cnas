# 版本记录：v0.34-image-rhythm-closure

## 1. 本轮目标

本轮目标是对上一轮上线收口基础上的图片系统再做一次高优先级修正，核心原则只有一条：

“图片如果不能增强高级感，就宁可不要。”

本轮不是扩充图片，而是重新判断哪些图片该保留、哪些图片该删除、哪些图片要统一比例和移动端高度。

本轮属于：

- 上线质感收口
- 可维护性提升
- 视觉噪音控制

## 2. 背景与上下文

本轮直接承接：

- `custom/notes/v0.33-launch-ready-mobile-closure.md`
- `custom/notes/v0.32-real-scene-image-system.md`

`v0.32` 的方向是把真实场景图系统接入站点，重点解决“页面过于纯文字”的问题。
`v0.33` 的方向是把整站压到更适合上线展示的 mobile-first 节奏。

但在 `v0.33` 落地后，出现了一个新的判断标准：

- 不是所有真实图都值得保留
- 竖幅图在 Hero 和正文中部很容易破坏节奏
- 图片一旦压缩不稳，反而会削弱专业感

因此本轮要修正的，不是“有没有图”，而是“图值不值得存在”。

## 3. 问题分析

本轮前的主要问题有四类：

1. 首页 Hero 图和诊断页 Hero 图虽然真实，但对当前这种判断型平台来说并不是必须项，而且竖幅图进入首屏后容易让布局显得偏重
2. 知识详情页中部插图虽然增强了“现场感”，但会打断阅读节奏，且图片本身并不具备足够强的构图优势
3. 底部 CTA 区块加入图片后，虽然增加了真实感，但也让底部收口从“干净”变成了“有点负担”
4. 方案卡和案例卡中的图片仍需要更统一的比例和移动端高度，否则会出现卡片密度不齐

真正的核心矛盾是：

这个站点需要的是“少量高质量辅助图”，而不是“每个能放图的位置都放一张图”。

## 4. 候选方案比较

### 方案一：所有已有图片继续保留，只调统一比例

核心思路：
不删图，只通过比例和高度统一来解决问题。

优点：

- 改动最少
- 图片系统完整保留

缺点：

- 一些本质上不该出现的图依然会留在页面里
- Hero 和正文插图的问题不是比例，而是“存在本身”

放弃原因：
不能真正满足“高级感优先于有图”的新原则。

### 方案二：删除不必要图片，只保留真正有价值的位置，再统一比例

核心思路：
把 Hero 图、正文插图、底部 CTA 图作为可删项处理；保留方案卡、案例卡和方案详情图，并统一成更克制的显示方式。

优点：

- 更符合内容平台气质
- 图片变成辅助，而不是负担
- 移动端节奏更容易稳定

缺点：

- 页面视觉上会更“克制”，少一部分现场感
- 需要重新判断哪些位置值得保留

最终选择原因：
更符合当前阶段“上线展示版”的目标。

## 5. 最终决策

本轮最终采用方案二，具体原则如下：

1. 首页 Hero 图删除
2. 诊断页 Hero 图删除
3. 知识详情页中部插图删除
4. 底部 CTA 图删除
5. 方案卡、案例卡、方案详情 Hero 图保留
6. 保留图片统一为更短、更稳定的比例，并限制移动端高度

## 6. 具体实现

本轮实际修改如下：

- `app/page.tsx`
  - 删除首页 Hero 图片与首页统计图区域
  - 保留纯文字 Hero，让标题、说明和 CTA 更稳

- `app/diagnosis/page.tsx`
  - 删除诊断页 Hero 图片
  - 保持首屏只围绕风险判断和 CTA 展开

- `app/knowledge/[slug]/page.tsx`
  - 删除正文中部插图
  - 恢复连续阅读节奏

- `components/CtaBlock.tsx`
  - 删除底部 CTA 配图
  - 改回更轻的纯文案转化区

- `components/SolutionCard.tsx`
  - 保留图片
  - 移动端改为 `h-40`
  - 桌面端统一为 `4:3`

- `components/CaseCard.tsx`
  - 保留图片
  - 移动端改为 `h-40`
  - 桌面端统一为 `4:3`

- `app/solutions/[slug]/page.tsx`
  - 方案详情 Hero 图保留
  - 移动端限制为更短的 `h-44`
  - 桌面端统一为 `4:3`

## 7. 本轮优点

本轮之后的直接收益：

- 首页和诊断页首屏明显更干净
- 知识详情页阅读连续性更好
- CTA 区块更轻，不再有“底部还要看一张图”的负担
- 保留下来的图片都更接近统一卡片系统，而不是零散素材
- 移动端图片不再容易把文字压下去

## 8. 本轮缺点与代价

本轮也有清晰代价：

- 站点整体图片数量减少，现场感会比上一轮更弱一点
- 首页不再通过首屏图建立“实验室现场感”，而改为更偏文字判断平台
- 如果后续拿到更高质量、更适合横向裁切的真实图，可能还会重新考虑 Hero 图位置

这些代价是本轮主动接受的，因为当前更重要的是“稳定气质”，而不是“图片存在感”。

- `npm run typecheck`
- `npm run build`
- 本地页面检查首页、诊断页、方案页、知识详情页和案例卡展示

本记录新增时，代码修改已完成，验证将在本轮收尾阶段执行。

## 10. 本轮结论

本轮最重要的结论是：

对于这个项目，图片不是默认资产，而是需要被严格筛选的内容。

只要图片不能显著增强高级感、真实感和秩序感，就应该删掉，而不是勉强保留。

## 11. 下一轮建议

1. 在真实移动端宽度下复核卡片图区高度是否还需要再压一档，例如 `h-36`
2. 如果后续继续补图，优先补“横向构图稳定、设备或人物主体清晰”的图，而不是再用竖幅图硬裁
3. 如果准备正式演示客户，可再做一轮“图片存在必要性”逐页审查
