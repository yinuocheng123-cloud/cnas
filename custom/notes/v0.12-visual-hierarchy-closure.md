# 版本记录：v0.12-visual-hierarchy-closure

## 1. 本轮目标

本轮目标是按“高级感与比例平衡”继续收口全站视觉层级：弱化导航、减少线条存在感、统一卡片结构、弱化次级按钮和非关键视觉元素。

目标类型：视觉层级优化、组件样式收口。

## 2. 背景与上下文

本轮承接 `custom/notes/v0.11-home-hero-balance.md`。上一轮已优化首页首屏标题比例，本轮继续从全站通用组件入手，使页面整体更克制，不改变内容结构、路由或导航数据。

## 3. 问题分析

当前页面结构已经清晰，但导航、卡片和局部边框的视觉权重仍偏强。对于 B 端专业内容平台，导航不应抢内容，卡片不应像营销模块，按钮也应只有主动作突出。

## 4. 候选方案比较

方案一：逐页修改样式。

优点是精细。缺点是改动分散、容易造成页面不一致，因此放弃。

方案二：优先修改 Header、Hero 和通用卡片组件。

优点是影响面集中，可快速统一全站气质，也更符合当前组件化结构。最终选择该方案。

## 5. 最终决策

弱化 Header 字号、颜色和下拉阴影；移除 Hero 底部分割线；将 ArticleCard、CategoryCard、SolutionCard、CaseCard、ServiceCard、ChecklistBlock 统一为轻边框、弱阴影结构；将方案卡片中的“查看详情”从深色按钮降级为轻按钮。

## 6. 具体实现

修改 `components/Header.tsx`：导航小字、浅色、低权重，下拉菜单轻边框和弱阴影。

修改 `components/HeroSection.tsx`：减少分割线存在感，保持更多留白。

修改主要卡片组件：统一 `border-slate-100`、轻阴影和低对比 hover。

修改 `components/ServiceCard.tsx` 与 `components/ChecklistBlock.tsx`：清单左侧强调线从蓝色粗线改为浅灰细线。

## 7. 本轮优点

页面更像专业知识平台而不是展示型官网；导航退后，内容成为主体；卡片结构更统一，主按钮层级更清楚。

## 8. 本轮缺点与代价

视觉对比降低后，个别入口的点击感会更克制，需要依赖布局和文案本身建立可点击预期。当前未引入图标，也没有做复杂动效。

## 9. 验证与结果

本轮需要执行 `npm run typecheck`、`npm run build`，并验证首页 `/` 返回 200。

## 10. 本轮结论

通过通用组件收口，站点整体视觉已进一步从“展示型官网”靠近“内容型专业平台”。

## 11. 下一轮建议

后续如继续优化，应基于浏览器截图微调具体页面的间距和移动端导航交互。
