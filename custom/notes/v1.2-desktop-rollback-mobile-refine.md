# 版本记录：v1.2-desktop-rollback-mobile-refine

## 1. 本轮目标

本轮目标是立即修复上一轮主站首页过度整合问题：电脑版恢复原 CNAS认可指南主站首页布局和内容结构，手机版只保留轻量路径判断引导，`path.cnaszhinan.com` 恢复为独立成交页。

本轮属于上线后问题修复，不新增后台、不新增数据库、不重构线索系统，不修改成交页内容。

## 2. 背景与上下文

本轮承接 `custom/notes/v1.1-mobile-first-path-integration.md` 和 `custom/notes/post-launch-operation-check.md`。

上一轮把 path 成交页核心逻辑完整整合进主站首页，并把 `path.cnaszhinan.com` 301 到主站 `#path-check`。用户反馈该方案导致电脑版首页变成成交页风格，破坏了原 CNAS认可指南主站的首页结构。因此本轮改为：桌面恢复原主站，移动端轻量吸收路径判断逻辑，成交页继续独立存在。

## 3. 问题分析

上一轮问题不在接口或后台，而在信息架构：把成交页完整转化链路前置到主站首页后，桌面端失去了原本“知识入口、风险判断、行业方案、案例解析”的主站定位。

本轮修复的关键是只回退首页主体，不回退备案号、footer 二维码、公开风险词修正、线索接口兼容等必要上线改动。

## 4. 候选方案比较

方案一：直接 `reset --hard` 到旧提交。

优点是最快恢复旧页面。缺点是会丢失后续备案、二维码、记录和风险词修正，也有误伤线上修复的风险。本轮放弃。

方案二：只从稳定提交恢复 `app/page.tsx` 首页主体，保留 footer 与其它必要修复。

优点是改动边界清楚，能恢复电脑版主站，同时保留上线后必要补丁。本轮采用。

方案三：继续在上一轮新组件上做响应式分流。

优点是代码复用多。缺点是新组件本身就是“成交页式首页”的来源，继续保留容易再次误用。本轮放弃，并删除该组件。

## 5. 最终决策

最终采用“局部恢复首页主体 + 保留 footer 优化 + 移动端轻量引导 + 撤回 path 301”的方案。

## 6. 具体实现

- `app/page.tsx`：从稳定提交 `5204864908d0ecee9d341b3d248c5b0dab16e1eb` 恢复电脑版首页主体，再只调整移动端 `md:hidden` 区块。
- `components/MobileFirstPathHome.tsx`：删除上一轮新增的整页成交式首页组件，避免继续作为首页主体使用。
- `components/Footer.tsx`：保留三栏 footer，并调整服务内容为 `CNAS认可流程`、`CNAS认可路径判断`、`评审准备`、`认可后维护`；右栏继续展示主站二维码 `/wecom-qr.png`；备案号保持 `浙ICP备2020044218号-3`。
- `public/wecom-qr.png`：继续作为主站公开二维码资源，不直接引用成交页目录。
- Nginx：撤回 `path.cnaszhinan.com` 到主站的 301，恢复成交页独立访问。未修改成交页内容，未删除 `/www/wwwroot/cnas-path`。

## 7. 本轮优点

- 电脑版首页重新回到 CNAS认可指南主站的内容结构和风格。
- 移动端仍保留路径判断导向，但不再堆长表单和整块成交页内容。
- Footer 继续承担企业微信承接、服务内容和备案展示。
- path 成交页恢复独立访问，投放入口不被提前下线。
- 主站后台、线索接口、备案号、HTTPS 和 PM2 均不受影响。

## 8. 本轮缺点与代价

移动端当前是轻量引导，不在首页直接完成完整表单提交。用户如果需要更强转化，仍应进入 `/diagnosis` 或独立成交页完成更完整留资。

本轮没有做新的 UI 视觉大改，只做结构修复和轻量调整，因此手机端仍需要用户实际浏览确认首屏、按钮和 footer 二维码的观感。

## 9. 验证与结果

本地验证：

- `npm run build`：通过。
- `npm run typecheck`：通过。
- 公开代码风险词检查：`app`、`src`、`components`、`lib` 下未发现 `CNAS认证`、`包过`、`保证通过`、`官方指定`、`唯一`、`最权威`、`必过`、`100%通过`。

Nginx 验证：

- 已恢复 `/www/server/panel/vhost/nginx/path.cnaszhinan.com.conf.bak-main-integration-20260526`。
- `nginx -t`：通过。
- `nginx reload`：已执行。
- `https://path.cnaszhinan.com`：返回 200。
- `http://path.cnaszhinan.com`：只跳转到 `https://path.cnaszhinan.com/`，不再跳主站。

## 10. 本轮结论

本轮已纠正上一轮“桌面首页成交页化”的方向错误。后续主站桌面端应继续保持 CNAS认可指南内容入口定位；移动端可以轻量引导路径判断，但不应把独立成交页整页搬入主站首页。

## 11. 下一轮建议

1. 用户用电脑端确认首页是否已回到原 CNAS认可指南风格。
2. 用户用手机端确认轻量路径判断入口是否清爽。
3. 保留 `path.cnaszhinan.com` 作为独立成交页，后续是否合并应等主站桌面和移动体验都确认后再决定。
