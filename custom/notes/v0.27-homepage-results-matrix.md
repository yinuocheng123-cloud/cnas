# 版本记录：v0.27-homepage-results-matrix

## 1. 本轮目标

本轮目标是把首页原本分散的“行业方案”和“案例解析”整合为一个更偏判断的“结果矩阵区”，让首页从栏目型浏览进一步转向决策型浏览。

本轮优先级属于：

- 首页信息架构收口
- 决策路径强化
- 最小结构调整

## 2. 背景与上下文

本轮承接以下记录：

- `custom/notes/v0.26-homepage-three-column-gap-tightening.md`
- `custom/notes/v0.25-case-dropdown-four-columns.md`

此前首页已经完成了密度收紧和导航下拉整理，但“行业方案入口”和“案例解析”仍然是两个彼此独立的 section。这样虽然结构清楚，却更像内容栏目，而不是帮助用户快速判断自己应看哪条路径的面板。

本轮延续“更像专业判断工具平台”的方向，不增加新组件，只在首页内重组现有内容板块。

## 3. 问题分析

修改前的核心问题有三点：

1. “行业方案”和“案例解析”在信息上本来是前后关系，但页面上呈现为两个平行栏目。
2. 用户需要自己在脑中完成“我属于哪种场景”和“别人容易在哪出问题”的串联，认知成本偏高。
3. 现有结构更像目录分发，不够像面向决策的路径面板。

真正的矛盾不是内容不够，而是内容之间缺少一条更明确的阅读顺序。

## 4. 候选方案比较

### 方案一：保留两个独立 section，只微调标题文案

优点：

- 改动最小
- 不动现有页面节奏

缺点：

- 结构关系没有变化
- 仍然偏“栏目型页面”

放弃原因：只能改善表述，无法真正改变信息架构。

### 方案二：合并为一个总 section，在区块内拆分“场景判断”和“问题判断”

优点：

- 能把阅读路径从“看栏目”改成“先看场景，再看问题”
- 可继续复用现有 `SolutionCard` 和 `CaseCard`
- 不需要新增复杂组件

缺点：

- 首页单区块内容会变得更集中，需要依靠文案层级维持可扫读性

最终选择原因：最符合“结果矩阵区”的目标，也能控制改动范围。

## 5. 最终决策

本轮最终采用以下方式：

1. 删除首页中原本独立的“行业方案入口”和“案例解析”两个 section。
2. 新建一个总 section，标题聚焦为“先看你更接近哪一种情况”。
3. 在该 section 内按阅读顺序拆成两个子区：
   - 按行业场景判断路径
   - 按典型问题判断风险
4. 在区块底部增加一个统一诊断出口，把用户自然引到 `/diagnosis`。

## 6. 具体实现

本轮修改文件如下：

- `app/page.tsx`
  - 将“行业方案入口”与“案例解析”合并到同一个总区块
  - 新增两个子标题和对应说明文案
  - 保留 `SolutionCard` 与 `CaseCard` 原有组件不变
  - 将案例区改为 `md:grid-cols-2 xl:grid-cols-4`，使四个案例更接近矩阵展示
  - 在区块底部加入统一诊断入口按钮

## 7. 本轮优点

本轮带来的正向效果：

- 首页信息架构更像决策面板，而不是内容目录
- 用户更容易形成“先看自己属于哪类，再看常见问题”的阅读路径
- 保留了现有卡片资产，没有额外引入复杂结构
- 统一诊断出口让转化路径更明确

## 8. 本轮缺点与代价

当前方案的已知取舍：

- 结果矩阵区的信息密度更高，对标题和说明文案的克制要求更高
- 目前只是首页层面的组织优化，尚未把“场景判断”与“问题判断”进一步映射到更细的筛选逻辑
- 案例区在超宽屏下改为四列，后续若卡片内容继续变长，可能需要再次检查可读性

## 9. 验证与结果

本轮计划执行以下验证：

- `npm run typecheck`
- `npm run build`

验证目标：

- 首页结构重组不引入类型错误
- 结果矩阵区在生产构建中可正常生成

## 10. 本轮结论

本轮最重要的结论是：首页要从“栏目型分发”走向“判断型承接”，关键不在于继续加内容，而在于把已有内容按用户决策顺序重排。把“行业方案”和“案例解析”放到同一个总区块后，这条路径更清晰了。

## 11. 下一轮建议

1. 可继续检查结果矩阵区与底部 `CtaBlock` 的角色是否有重复，决定是否进一步收口。
2. 如果继续强化首页判断感，可把“风险诊断”与“结果矩阵区”之间的过渡文案再压缩一轮。
3. 若后续需要更强导流，可考虑把行业方案和案例的卡片排序按转化优先级再排一次。
