# 版本记录：v0.46-home-hero-risk-matrix-restoration

## 1. 本轮目标

本轮只恢复首页 Hero 右侧原来的“四个风险数据卡片”，不改首页整体结构。

核心目标：

- 恢复顶部横向风险提示
- 恢复下方 2×2 风险数据卡片
- 让首页重新形成“左侧主叙事 + 右侧风险判断”的首屏结构

本轮属于：

- 首页结构恢复
- 首屏信息层级修正
- 风险判断面板回退

## 2. 背景与上下文

本轮承接：

- `v0.45-single-line-and-auto-fit-closure`
- `v0.41-hero-risk-panel-width-and-text-closure`

当前问题不是组件丢了，而是：

- `HeroSection` 右侧 `aside` 结构仍在
- `RiskEntryCard` 组件仍在
- `riskEntries` 数据源也仍在

但 `riskEntries` 被改成了纯判断型文案，失去了原本“数字 + 标题 + 一句话”的风险数据面板感，导致右侧视觉承载力下降，看起来像只剩一条提示条和大片空白。

## 3. 问题分析

表面现象：

- 首页右侧不再像风险矩阵
- 视觉锚点不足
- 左右失衡

核心矛盾：

首屏右侧需要的是“辅助判断面板”，不是单纯再放四句判断标题。

如果没有数字层级，卡片会更像普通链接列表，而不是风险证据区。

## 4. 候选方案比较

### 方案 A：保留当前纯判断文案卡片

优点：

- 更克制
- 文案更专业

缺点：

- 缺乏视觉锚点
- 右侧承载感不足
- 首屏失去辅助系统感

结论：

放弃。

### 方案 B：恢复数字化风险卡片，但控制说明长度

优点：

- 恢复右侧判断面板的视觉权重
- 仍然保持短句，不做长段解释
- 更符合“左叙事 + 右判断”的结构

缺点：

- 数字表达会比纯文字更显眼

结论：

采用。

## 5. 最终决策

恢复为：

- 顶部一条横向风险提示
- 下方 `2 × 2` 风险卡片
- 每张卡片结构统一为：
  - 数字
  - 标题
  - 一句话说明

## 6. 具体实现

### `src/data/riskEntries.ts`

- 为 `RiskEntry` 增加 `metric`
- 恢复四条数据化风险卡内容：
  - `127` / 能力范围偏差案例
  - `68%` / 返工来自路径误判
  - `31` / 设备路线错误案例
  - `4-6个月` / 平均返工周期

### `components/RiskEntryCard.tsx`

- 恢复卡片层级为：
  - 顶部数字
  - 中间标题
  - 底部一句说明
- 保持统一高度和简洁 hover

### `app/page.tsx`

- 首页 Hero 右侧网格明确收口为：
  - `grid grid-cols-2 gap-4`
- 保留原有 `riskNotice`
- 因此结构恢复为“顶部提示 + 下方 2×2”

## 7. 本轮优点

- 首页右侧重新有了明确视觉锚点
- 左右区块重新形成主次关系
- 风险卡片更像判断面板，而不是普通文本入口
- 改动小，没有推翻 Hero 结构

## 8. 本轮缺点与代价

- 数字表达比纯文字更显眼，右侧存在感会略上升
- 如果后续数字文案继续变长，仍需继续控制标题长度

## 9. 验证与结果

本轮完成后执行：

- `npm run typecheck`
- `npm run build`
- `npm run dev`

重点检查：

- 首页右侧是否恢复四宫格
- 顶部提示条是否仍保留
- 卡片高度是否一致
- 不出现长段堆叠

## 10. 本轮结论

首屏右侧真正需要的不是“再加四句判断”，而是“有层级的风险面板”。

数字、标题、短句三层结构，能更稳定地承担辅助判断系统的角色。

## 11. 下一轮建议

1. 如果还觉得右侧权重偏低，可再微调数字字号和卡片背景对比度
2. 如果还觉得偏强，则优先缩短说明句，而不是去掉数字层
