# 版本记录：v0.42-hero-risk-matrix-restoration

## 1. 本轮目标

恢复首页 Hero 右侧原来的“四个风险数据卡片”，并保留顶部横向风险提示。

核心目标：

- 恢复顶部横向风险提示
- 恢复下方 2×2 风险数据卡片
- 让首页重新形成“左侧主叙事 + 右侧风险判断”的首屏结构

本轮属于：

- 首页结构恢复
- 首屏信息层级修正
- 风险判断面板回退

## 2. 背景与上下文

当前问题不是组件丢了，而是：

- `HeroSection` 右侧 `aside` 结构仍在
- `RiskEntryCard` 组件仍在
- `riskEntries` 数据源也仍在

但 `riskEntries` 曾被改成纯判断型文案，失去了原本“数字 + 标题 + 一句话”的风险数据面板感，导致右侧视觉承载力下降。

## 3. 问题分析

表面现象：

- 首页右侧不再像风险矩阵
- 视觉锚点不足
- 左右失衡

核心矛盾：

首屏右侧需要的是“辅助判断面板”，不是单纯再放四句判断标题。

## 4. 候选方案比较

### 方案 A：保留当前纯判断文案卡片

优点：

- 更克制
- 文案更专业

缺点：

- 缺乏视觉锚点
- 右侧承载感不足

结论：

放弃。

### 方案 B：恢复数字化风险卡片，但控制说明长度

优点：

- 恢复右侧判断面板的视觉权重
- 仍然保持短句，不做长段解释
- 更符合“左叙事 + 右判断”的结构

结论：

采用。

## 5. 最终决策

恢复为：

- 顶部一条横向风险提示
- 下方 `2 × 2` 风险卡片
- 每张卡片结构统一为：
  - 数字
  - 标题
  - 一句话说明

## 6. 具体实现

### `src/data/riskEntries.ts`

- 为 `RiskEntry` 增加 `metric`
- 恢复四条数据化风险卡内容：
  - `127` / 能力范围偏差案例
  - `68%` / 返工来自路径误判
  - `31` / 设备路线错误案例
  - `4-6个月` / 平均返工周期

### `components/RiskEntryCard.tsx`

- 恢复卡片层级为：
  - 顶部数字
  - 中间标题
  - 底部一句说明
- 保持统一高度和简洁 hover

### `app/page.tsx`

- 首页 Hero 右侧网格明确收口为：
  - `grid grid-cols-2 gap-4`
- 保留原有 `riskNotice`

## 7. 本轮优点

- 首页右侧重新有了明确视觉锚点
- 左右区块重新形成主次关系
- 风险卡片更像判断面板，而不是普通文本入口

## 8. 本轮缺点与代价

- 数字表达比纯文字更显眼，右侧存在感会略上升

## 9. 验证与结果

已完成：

- `npm run typecheck`
- `npm run build`

并继续做 `dev` 实例与首页访问验证。

## 10. 本轮结论

首屏右侧真正需要的不是“再加四句判断”，而是“有层级的风险面板”。

## 11. 下一轮建议

1. 如仍觉得右侧权重偏低，可微调数字字号和卡片背景对比度
2. 如仍觉得偏强，优先缩短说明句，而不是去掉数字层
