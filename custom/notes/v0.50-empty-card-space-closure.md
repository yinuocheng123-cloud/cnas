# 版本记录：v0.50-empty-card-space-closure

## 1. 本轮目标

本轮目标是处理卡片内部出现明显空槽的问题，尤其是知识库分类卡片中标题与说明之间被强行撑开的空白。

本轮属于视觉体验修复，不新增功能、不调整内容逻辑、不改变 URL，只移除空占位与不必要的等高约束。

## 2. 背景与上下文

本轮承接 `v0.44-vertical-rhythm-tightening` 的全站节奏收口。上一轮解决的是模块之间留白过大的问题，本轮继续处理模块内部的空白断层。

用户指出截图中卡片标题和正文之间出现大块空白，这类问题不能只修局部，需要扫描其它卡片是否也存在类似现象。

## 3. 问题分析

问题主要来自三类写法：

1. 标题和说明文字使用 `md:min-h-[...]`，短标题也会占用两行高度，形成空槽。
2. 卡片全局 `.card-link` 默认 `h-full`，配合 grid 的默认 stretch，会让短内容卡片被拉高。
3. 部分按钮使用 `mt-auto`，在内容较短时会把按钮推到底部，中间留下大片空白。

这类空白和上一轮 section 间距不同，它发生在卡片内部，更容易让用户觉得页面“空、散、不完整”。

## 4. 候选方案比较

方案一：保留等高卡片，只缩小 min-height。

- 优点：卡片行高仍然整齐。
- 缺点：仍会有空槽，只是变小。
- 结论：放弃。

方案二：去掉卡片内部 min-height，改为自然内容高度。

- 优点：直接消除空槽，内容关系更紧凑自然。
- 缺点：同一行卡片高度可能不完全一致。
- 结论：采用。当前站点更需要阅读体验，不需要牺牲内容节奏追求机械等高。

方案三：保留等高，但增加装饰元素填满空白。

- 优点：视觉上不空。
- 缺点：会引入无意义装饰，违背克制专业原则。
- 结论：放弃。

## 5. 最终决策

本轮统一移除卡片标题、摘要、按钮区域中的硬撑高度：

- `CategoryCard` 移除标题和说明的 `md:min-h`。
- `SolutionCard` 移除标题、摘要 `md:min-h` 和按钮 `mt-auto`。
- `CaseCard` 移除卡片 `h-full`、标题/摘要 `md:min-h` 和按钮 `mt-auto`。
- `ProcessSteps` 移除步骤卡片 `md:min-h-40` 与标题 `md:min-h`。
- `.card-link` 从公共 token 中移除 `h-full`。
- 多个 grid 增加 `items-start`，让卡片自然高度顶部对齐。

## 7. 本轮优点

- 知识库分类卡片不再出现标题和正文之间的大空槽。
- 方案、案例、流程、文章列表卡片不再为短内容强行预留高度。
- 卡片阅读节奏更接近真实内容流，不像模板占位。
- 保留了卡片结构、边框、按钮和原有内容，没有引入新样式系统。

## 8. 本轮缺点与代价

- 同一行卡片高度可能不完全一致。
- 个别带图片的方案卡片仍然会因为图片比例保持统一而有固定视觉高度，这是为了图片一致性保留的约束。
- Hero 风险矩阵仍保留最小高度和等高结构，因为它属于数值矩阵，不属于本轮截图中的内容空槽问题。

## 9. 验证与结果

本轮已执行：

- `npm run typecheck`：通过。
- `npm run build`：通过，Next.js 成功生成 87 个页面。

重点确认：

- 分类卡片标题与说明之间不再由 `md:min-h` 产生空白占位。
- 方案卡、案例卡、流程卡已去掉普通内容卡片中的硬撑高度。
- 首页、知识库、方案页、案例页构建正常。

## 10. 本轮结论

内容型平台的卡片不应优先追求机械等高，尤其是短标题、短摘要的内容入口。对于知识、方案、案例入口，顶部对齐和自然内容高度更符合阅读体验。

## 11. 下一轮建议

1. 用浏览器复核 `/knowledge` 和首页 PC 端分类区。
2. 若后续仍有局部空槽，优先检查 `min-h`、`h-full`、`mt-auto` 三类 class。
3. 对 Hero 风险矩阵继续单独维护，不跟普通内容卡片混用规则。
