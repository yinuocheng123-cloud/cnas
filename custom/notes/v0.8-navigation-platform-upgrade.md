# 版本记录：v0.8-navigation-platform-upgrade

## 1. 本轮目标

本轮目标是执行全站导航结构升级，把站点从单层展示型导航进一步调整为“内容型 + 转化型 CNAS专业平台”导航。

目标类型：信息架构优化、导航升级、内容承接增强、SEO结构收口。

## 2. 背景与上下文

本轮承接 `custom/notes/v0.7-home-diagnosis-density.md` 和 `custom/notes/v0.6-production-readiness.md`。上一轮已增强首页风险诊断区和流程步骤注解，本轮继续围绕“CNAS专业内容平台”定位，重点处理顶部导航、下拉内容体系、首页路径联动和 sitemap 空入口风险。

本轮开始前执行 `git pull --ff-only`，远端返回 `Already up to date`。

## 3. 问题分析

原导航只有一级链接，用户能进入主要页面，但无法看出全站内容体系和转化路径。知识库、流程、方案、案例、诊断、服务之间的定位差异不够直观，搜索引擎也缺少更清晰的栏目层级信号。

核心矛盾是：页面内容已经接近专业平台，但导航仍偏“官网栏目展示”，需要升级为可长期扩展的内容入口体系。

## 4. 候选方案比较

方案一：只替换一级导航文字。

优点是改动很小。缺点是无法体现内容体系，也无法承接流程步骤、行业方案、案例标签和服务模块，因此放弃。

方案二：一级导航控制在 7 个以内，下拉菜单承接栏目体系，新增必要内容落点。

优点是既满足长期扩展，又不引入复杂 CMS 或后台。缺点是需要补齐部分方案和案例数据，避免下拉入口为空。最终选择该方案。

## 5. 最终决策

保留 7 个一级入口：首页、CNAS知识库、CNAS认可流程、行业方案、案例解析、风险诊断、服务咨询。

下拉菜单分别承接内容体系：知识库走分类页，流程走同页步骤锚点，行业方案走方案详情页，案例走案例锚点，风险诊断和服务咨询走对应页面锚点。

## 6. 具体实现

修改 `lib/site-data.ts`：扩展 `NavItem`，新增下拉数据、首页路径数据和流程阶段数据；补齐高校/科研实验室与集团内部实验室两个行业方案。

修改 `components/Header.tsx`：支持一级导航下拉菜单，并标注栏目意图。

修改 `app/page.tsx`：新增“平台路径”模块，使首页模块与知识库、流程、方案、案例、诊断导航入口对应。

修改 `app/cnas-process/page.tsx`：由单纯分类页升级为流程拆解页，并保留相关文章列表。

修改 `app/diagnosis/page.tsx`、`components/ServiceCard.tsx`、`components/CaseCard.tsx`：增加锚点承接导航下拉入口。

修改 `src/data/cases.ts`：为案例增加标签，并补充评审失败翻盘案例。

修改 `app/sitemap.ts` 和 `app/tags/[tag]/page.tsx`：仅收录有文章的标签页，避免空标签入口进入 sitemap。

## 7. 本轮优点

导航结构更清晰，每个栏目有明确定位：知识库承接流量，流程承接强需求，方案和服务承接成交，案例承接信任，诊断承接转化。新增下拉结构也为后续内容扩展保留了稳定入口。

## 8. 本轮缺点与代价

当前下拉菜单仍是静态数据，未来如果内容规模扩大，可能需要把导航配置进一步拆分到独立数据文件。流程子栏目目前以锚点承接，没有为每一步单独创建页面，这是为了避免出现内容稀薄的空页面。

## 9. 验证与结果

本轮已执行 `npm run typecheck`。后续需要继续执行 `npm run build` 并检查关键页面访问状态。

## 10. 本轮结论

采用“一级入口 + 下拉体系 + 非空落点”的方式，比新增大量薄页面更适合当前 Demo 阶段。它能提升结构清晰度，同时避免 sitemap 收录无内容页面。

## 11. 下一轮建议

第一，若后续内容增加，可将流程每一步拆成独立文章聚合页。

第二，移动端可继续优化下拉导航交互，必要时增加折叠菜单。

第三，行业方案新增页面后，应继续补充更具体的案例和FAQ，增强成交页深度。
