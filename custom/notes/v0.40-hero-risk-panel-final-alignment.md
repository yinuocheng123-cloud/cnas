# 版本记录：v0.40-hero-risk-panel-final-alignment

## 1. 本轮目标
本轮不再改首页结构，只收口首页首屏 Hero 与右侧风险卡片的视觉层级。

核心目标：
- 让左侧 Hero 明确保持主视觉
- 让右侧风险矩阵降级为辅助风险提示系统
- 解决首屏左右“像两个 Hero 同时存在”的问题

本轮属于：
- 首页首屏层级收口
- 风险矩阵视觉降级
- 移动端节奏微调

## 2. 背景与上下文
本轮承接：
- `custom/notes/v0.39-risk-card-alignment-closure.md`
- `custom/notes/v0.38-hero-risk-entry-matrix.md`
- `custom/notes/v0.37-risk-driven-decision-platform-refinement.md`

延续结论：
- `v0.38` 已经确认首页右侧需要保留风险矩阵，不能回到空白区
- `v0.39` 已经去掉硬数字，解决了“营销统计感”

本轮继续修正的点：
- 虽然数字已经删掉，但右侧卡片的标题字号、宽度和信息密度仍偏重
- 左侧容器仍带有居中倾向，导致左右重心不够一致

## 3. 问题分析
本轮开始前首屏的主要问题有三类：

1. 左右顶边没有形成足够稳定的起始线
- Hero 虽然整体是两栏，但左侧内容区仍带 `justify-center`
- 这会让右侧矩阵在视觉上更像独立第二主区

2. 右侧卡片权重过高
- 标题字号偏大
- 卡片文本块偏满
- 矩阵宽度略宽，容易和 Hero 形成对抗

3. 顶部提示条过长
- 风险提示条本来只是辅助，但文案较长时会变成又一段正文

核心矛盾不是内容对不对，而是主辅关系还没有真正拉开。

## 4. 候选方案比较
### 方案 A：继续缩 Hero 左侧标题
- 优点：能快速让右侧不那么抢眼
- 缺点：会削弱首页主判断系统，不符合本轮目标
- 结论：放弃

### 方案 B：保留左侧权重，降低右侧矩阵级别
- 优点：直接修正首屏主辅关系
- 缺点：需要精细处理字号、宽度、提示条和对齐
- 结论：采用

## 5. 最终决策
最终采用以下收口方式：

1. 左右容器统一顶部对齐，去掉左侧的垂直居中倾向
2. 右侧栏宽度从 360px 收到 328px，减少压迫感
3. 风险卡片标题降到 `text-base / leading-6`
4. 风险卡片统一 `min-h-[150px]`，保证 2×2 齐平
5. 风险提示条改成一句短判断，保持 `text-sm / leading-6`

## 6. 具体实现
### `components/HeroSection.tsx`
- 将 balanced Hero 的整体和左侧内容区统一为 `items-start / justify-start`
- 缩窄桌面端右侧栏宽度到 `328px`
- 风险提示条统一改为 `text-sm` 和 `leading-6`

### `components/RiskEntryCard.tsx`
- 标题由 `text-lg` 收到 `text-base`
- 统一卡片最小高度为 `150px`
- 保持两行截断和统一 padding

### `src/data/riskEntries.ts`
- 按本轮要求替换为更短的四组判断式文案

### `app/page.tsx`
- 将顶部风险提示条替换为一句短提示

## 7. 本轮优点
- 首屏重新回到“左主右辅”的主次关系
- 右侧风险卡片保留信息承载，但不再像第二组 Hero
- 风险提示条更克制，不再拉高右侧视觉重量
- 移动端依旧保持单列，不增加结构复杂度

## 8. 本轮缺点与代价
- 右侧卡片信息量进一步压缩，单卡表达空间更有限
- 由于不改结构，首屏的最终张力仍然受当前 Hero 框架约束
- 当前的截断与最小高度仍是组件内写法，后续若有更多同类卡片，可能还要抽统一工具类

## 9. 验证与结果
本轮计划执行：
- `npm run typecheck`
- `npm run build`
- `npm run dev`

重点检查：
- 首页是否返回 200
- Hero 左右是否严格顶部对齐
- 风险卡片是否齐平且不再抢视觉
- 移动端是否保持单列稳定

## 10. 本轮结论
- 首屏的核心不是再加信息，而是把主辅关系拉开
- 对当前站点来说，右侧风险矩阵最合适的定位是“辅助风险提示”，不是“第二主叙事”
- 缩窄栏宽、收标题字号、缩短提示条，比继续改结构更符合当前收口阶段

## 11. 下一轮建议
1. 用浏览器实际复核桌面端首屏左右顶边和 CTA 首屏可见性
2. 若后续继续精修首页，可单独处理 Hero 左侧标题断行节奏
3. 继续保持右侧矩阵只承接短判断，避免再次膨胀成信息主区
