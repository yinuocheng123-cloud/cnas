# 版本记录：v0.56-production-launch-audit

## 1. 本轮目标

本轮目标是对准备上线的 CNAS认可指南站点做一次只读上线前深度检视，判断当前版本是否具备明天上线条件，并列出上线前必须确认、建议补充和可延后优化的事项。

## 2. 背景与上下文

本轮承接 `v0.52`、`v0.53`、`v0.54` 的首页风险数据、案例按钮对齐和卡片等高收口结果。当前项目已经完成内容结构、移动端首页简化、卡片视觉收口、SEO 基础配置、线索提交 API 和轻量后台。

## 3. 问题分析

当前站点的页面结构和构建状态已经接近可上线，但上线风险主要集中在四类：

1. 正式域名环境变量未确认时，sitemap、robots、canonical 和 Open Graph 会使用本地默认域名。
2. 依赖安全审计发现 Next.js 与 PostCSS 相关漏洞，需要上线前处理。
3. 线索存储仍使用本地 `data/leads.json`，在 serverless 或无持久磁盘环境中不可靠。
4. `npm run lint` 仍使用已废弃的 `next lint`，会进入交互配置流程，不适合作为上线检查脚本。

## 4. 候选方案比较

方案一：直接上线当前版本。

- 优点：页面可访问，构建通过，核心内容已完整。
- 缺点：域名 SEO、依赖安全和线索持久化存在上线风险。
- 结论：不建议完全无处理直接上线。

方案二：上线前只处理必要配置和安全项，不做视觉与内容重构。

- 优点：风险收益比最高，不影响既有页面稳定性。
- 缺点：线索存储如果不接数据库，仍只能作为过渡方案。
- 结论：建议采用。

方案三：上线前接入完整数据库和后台。

- 优点：线索和内容管理更长期。
- 缺点：明天上线前引入过多变量，可能破坏当前稳定状态。
- 结论：放到上线后迭代。

## 5. 最终决策

当前版本可以作为上线试运行候选，但上线前必须完成：

1. 配置正式 `SITE_URL`。
2. 修复或确认依赖安全审计项。
3. 明确线索接收方式，优先使用 webhook 或外部持久化。
4. 清理部署源中的本地日志、截图、工具和测试线索数据。

- `npm run build` 通过，生成 87 个页面。
- 核心页面、知识库、方案页、诊断页、分类页、标签页、sitemap、robots 抽检均返回 200。

## 8. 本轮缺点与代价

- `npm audit --omit=dev` 仍报告 1 个 high 和 1 个 moderate 漏洞。
- `npm run lint` 不可作为自动检查脚本，会进入 Next.js 旧 lint 交互配置。
- sitemap 和 robots 在未配置 `SITE_URL` 时会输出 `http://localhost:3000`。
- 线索提交会写入本地 JSON，不适合长期 serverless 生产环境。
- `app/api/lead/route.ts` 当前会打印完整线索记录，生产日志中可能出现联系方式。

## 10. 本轮结论

当前版本具备上线试运行基础，但不建议在未处理依赖安全、正式域名环境变量和线索接收方式前直接正式对外推广。最稳妥的上线方式是先做配置与安全收口，再部署为生产预览或小流量正式站。

## 11. 下一轮建议

1. 上线前优先执行 `npm audit fix` 或升级 Next.js 到安全版本，并重新运行 `typecheck` 与 `build`。
2. 配置正式 `SITE_URL`、`ADMIN_KEY`、`LEAD_WEBHOOK_FEISHU` 或 `LEAD_WEBHOOK_WECHAT`。
3. 若部署到 Vercel 等 serverless 平台，尽快把线索存储迁移到数据库或外部表单服务。
