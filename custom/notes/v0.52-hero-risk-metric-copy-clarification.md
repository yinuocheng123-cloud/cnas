# 版本记录：v0.52-hero-risk-metric-copy-clarification

## 1. 本轮目标

本轮目标是修改首页 Hero 右侧四个风险数据卡片的文案，让数字表达更清楚、更容易理解。

本轮属于前台内容表达收口，不新增功能，不改变首页结构，不调整 URL，也不重构组件。

## 2. 背景与上下文

本轮承接以下历史记录：

- `custom/notes/v0.40-hero-risk-panel-final-alignment.md`
- `custom/notes/v0.41-hero-risk-panel-width-and-text-closure.md`
- `custom/notes/v0.42-hero-risk-matrix-restoration.md`
- `custom/notes/v0.43-mobile-homepage-simplification.md`

历史结论是：PC 首页右侧保留 2×2 风险矩阵，移动端不展示四张大风险卡；风险卡应作为辅助判断区，不扩展成长解释模块。

## 3. 问题分析

原有风险卡中包含 `127` 和 `31` 这类孤立数字。虽然能制造数据感，但用户无法在第一眼理解数字来源和含义，容易产生“统计口径不清”的感觉。

当前首页定位是 CNAS 认可启动前的判断平台，风险数字应该帮助用户快速理解“这个数字在提醒什么”，而不是只展示一个难以解释的指标。

## 4. 候选方案比较

方案一：保留原数字，只补充更长解释。

- 优点：改动小。
- 缺点：会让卡片说明变长，破坏 Hero 右侧的短判断节奏。
- 结论：放弃。

方案二：替换为更直观的数字，并让标题直接解释数字含义。

- 优点：用户能一眼理解每个数字代表的风险；不需要增加长段解释。
- 缺点：部分标题会比原先更长，需要依赖现有两行以内展示能力。
- 结论：采用。

## 5. 最终决策

采用“数字本身更明确 + 标题解释数字 + 说明只保留一句话”的方式。

保留四卡结构：

- 数字
- 标题
- 一句话说明

同时删除旧的 `127` 和 `31`，保留并强化 `68%` 与 `4–6个月`。

## 6. 具体实现

修改文件：

- `src/data/riskEntries.ts`

具体调整：

- 第一张卡改为 `68% / 返工来自前期路线误判 / 真正的问题，往往不是评审阶段。`
- 第二张卡改为 `4–6个月 / 一次返工平均周期 / 很多时间，都浪费在重做。`
- 第三张卡改为 `3次以上 / 多数实验室调整过能力范围 / 很多问题，都是边做边改。`
- 第四张卡改为 `20万+ / 设备路线调整常见额外投入 / 设备一旦买错，后期成本更高。`

本轮未修改 `components/RiskEntryCard.tsx`，因为现有组件已经符合“数字 + 标题 + 一句话说明”的结构，并且保留了统一最小高度。

## 7. 本轮优点

- 风险数字更容易被用户理解，不再出现含义不明的孤立数字。
- 卡片标题直接解释数字含义，减少用户认知成本。
- 保持 Hero 右侧 2×2 风险矩阵结构不变。
- 没有增加长段解释，仍然符合首页首屏的克制表达。

## 8. 本轮缺点与代价

- `设备路线调整常见额外投入` 这类标题在较窄桌面宽度下可能显示为两行。
- 新数字仍属于 Demo 阶段表达，正式上线前如要用于严格对外宣传，建议补充真实统计口径或改为“常见风险提示”口吻。
- 本轮只改文案，没有新增数据来源说明模块。

## 10. 本轮结论

首页 Hero 风险矩阵更适合使用“能直接读懂含义”的数字，而不是只展示孤立统计值。标题需要承担解释数字的职责，说明句只保留风险判断，不扩展成详细解释。

## 11. 下一轮建议

1. 用浏览器复核 1440px 桌面宽度下四张卡的两行以内显示效果。
2. 若后续要进一步增强可信度，可以在相关知识库文章中解释这些风险判断的来源和适用边界。
3. 若移动端未来需要展示风险数据，建议仍采用轻量提示条，不恢复四宫格。
