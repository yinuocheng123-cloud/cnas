# 版本记录：v0.39-risk-card-alignment-closure

## 1. 本轮目标
本轮只收口首页两组卡片：

- Hero 右侧风险判断卡片
- 首页“查看返工案例”卡片

核心目标：
- 删除“127 / 68% / 31 / 4-6个月”这类无来源的营销统计感
- 改成更符合 CNAS 平台气质的行业判断式表达
- 统一首页卡片的高度、对齐、间距和节奏

本轮属于：
- 首页语言系统收口
- 卡片对齐优化
- 风险判断表达修正

## 2. 背景与上下文
本轮承接：
- `custom/notes/v0.38-hero-risk-entry-matrix.md`
- `custom/notes/v0.37-risk-driven-decision-platform-refinement.md`
- `custom/notes/v0.23-mobile-first-refinement.md`
- `custom/notes/v0.20-homepage-spacing-tightening.md`

延续结论：
- 首页 Hero 右侧需要保留“风险入口矩阵”，不能再回到空白装饰区
- 整站气质必须保持专业、克制、可信
- 移动端优先仍然是默认约束

本轮修正的旧思路：
- `v0.38` 用数字增强“证据感”的想法虽然能补信息密度，但数字没有明确来源，会引发营销统计感，和 CNAS 领域的专业可信要求冲突

## 3. 问题分析
本轮开始前主要有两个问题：

1. 风险矩阵太像营销统计模块
- 数字视觉权重太高，用户会先注意“127 / 68%”之类的数字，而不是判断本身
- 当数字没有来源说明时，反而会削弱可信度

2. 首页案例卡片天然不齐
- 标题长度不同
- 内容是三段式长文本
- 图片高度虽然接近，但文字区高度差会把按钮位置拉开

真正的核心矛盾不是“缺少信息”，而是“信息表达方式不像同一套判断系统”。

## 4. 候选方案比较
### 方案 A：保留数字，只弱化字号
- 优点：改动最小
- 缺点：营销统计感依旧存在，问题没有被真正解决
- 结论：放弃

### 方案 B：彻底删除数字，改成标题 + 一句判断
- 优点：更符合行业判断平台语气，也更稳
- 缺点：需要重新处理卡片高度和阅读节奏
- 结论：采用

### 方案 C：案例卡片继续保留三段正文，只靠固定高度拉齐
- 优点：保留信息最多
- 缺点：会变成视觉上被强行拉齐，实际阅读仍然很重
- 结论：放弃

## 5. 最终决策
最终采用：

1. Hero 风险卡片统一改成“标题 + 一句判断”
2. 删除 `riskEntries` 中的数字字段
3. 使用双行截断和最小高度，让四张卡片在桌面端齐平、移动端单列稳定
4. 首页案例卡片改成：
   - 统一 `4:3` 图片比例
   - 标题两行内
   - 只保留“原本计划”和“最终结果”两段摘要
   - CTA 用 `mt-auto` 锁到卡片底部

## 6. 具体实现
### `src/data/riskEntries.ts`
- 删除 `value` 字段
- 用用户指定的四组判断式文案替换原先数字型卡片内容

### `components/RiskEntryCard.tsx`
- 删除数字展示
- 标题改成 `text-lg + leading-snug + font-semibold`
- 说明改成 `text-sm + leading-6`
- 增加双行截断和桌面端最小高度，保证四张卡片齐平

### `components/CaseCard.tsx`
- 卡片改为 `flex h-full flex-col`
- 图片比例统一为 `4:3`
- 标题、摘要都增加两行截断
- 移除中间“发现风险后”段落，保留更利于扫读的两段式摘要
- CTA 区改为 `mt-auto`，保证按钮底部对齐

### `components/HeroSection.tsx`
- 仅把右侧组合区间距从 `gap-3` 收到更稳定的 `gap-4`

### `app/page.tsx`
- Hero 右侧矩阵改为 `items-stretch + gap-4`
- 首页案例区改为 `items-stretch + gap-4`

## 7. 本轮优点
- 首页 Hero 右侧不再像营销统计模块，更像专业机构的风险判断入口
- 风险卡片与案例卡片开始共享相近的节奏和层级
- 案例区移动端更容易扫读，CTA 更整齐
- 不增加新组件结构，只在现有实现上收口

## 8. 本轮缺点与代价
- 删除数字后，“证据感”更多依赖文案判断，而不再依赖强视觉符号
- 案例卡片为了对齐和扫读，首页里承载的信息比案例详情页更少
- 目前使用的是组件内截断样式，而不是全局抽象 class，后续如果同类卡片继续增多，可能需要再提炼

## 9. 验证与结果
本轮计划执行：
- `npm run typecheck`
- `npm run build`
- `npm run dev`

重点检查：
- 首页 Hero 风险卡片是否全部齐平
- 首页案例卡片按钮是否底部对齐
- 移动端是否仍保持单列且无挤压

## 10. 本轮结论
- 对当前站点来说，“专业判断感”比“数字证据感”更重要
- 如果数字没有明确来源，宁可删掉，也不要让首页出现营销统计感
- 首页案例卡片更适合做摘要式承接，而不是把详情页结构完整搬进卡片

## 11. 下一轮建议
1. 用浏览器实际复核首页 Hero 风险卡片和案例卡片在桌面与手机端的齐平程度
2. 如果后续继续做首页收口，可把常见的两行截断样式提炼为统一工具类
3. 若要继续增强可信度，优先补更细的返工场景专题页，而不是重新引入数字表达
