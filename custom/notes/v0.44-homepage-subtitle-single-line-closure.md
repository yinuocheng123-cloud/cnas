# 版本记录：v0.44-homepage-subtitle-single-line-closure

## 1. 本轮目标

本轮只处理首页“平台路径”区域标题下方的说明文字，不改结构。

核心目标：

- 让桌面端恢复单行展示
- 保持移动端自然换行
- 避免说明文字形成松散的段落感
- 让标题区更像平台级判断说明，而不是宣传型说明段落

本轮属于：

- 排版收口
- 信息密度优化
- 首页局部样式修正

## 2. 背景与上下文

本轮承接：

- `v0.43-navigation-minimalization-closure`
- `v0.42-platform-closure-and-recommendation-chain`

当前首页“先判断方向，比边做边改更省成本”这一块，说明文字在桌面宽度下被折成两行。原因不是文案本身过长，而是 `SectionTitle` 默认给说明文字套了 `max-w-2xl`，导致桌面端宽度被人为压窄。

## 3. 问题分析

表面现象：

- 说明文字在 1366 / 1440 桌面宽度下折成两行
- 区块看起来更松、更拖
- 标题和说明宽度关系失衡

核心矛盾：

这块文案更适合作为“一行判断说明”，而不是独立小段落。

如果直接全局修改 `SectionTitle` 默认宽度，会影响其他 section 的节奏，因此本轮更适合做定点修正。

## 4. 候选方案比较

### 方案 A：全局修改 `SectionTitle` 默认样式

优点：

- 改一次，所有 section 都可能更宽

缺点：

- 风险高
- 容易破坏其他页面和移动端节奏

结论：

放弃。

### 方案 B：只给首页这个区块补 `descriptionClassName`

优点：

- 改动最小
- 只影响目标区块
- 可以精确做到“桌面单行，移动端正常换行”

缺点：

- 规则没有沉到全局默认

结论：

采用。

## 5. 最终决策

最终采用局部覆盖样式：

- 保留 `SectionTitle` 默认实现不动
- 仅在首页目标区块传入：
  - `whitespace-normal`
  - `md:whitespace-nowrap`
  - `md:max-w-6xl`
  - `leading-7`

这样桌面端单行，移动端仍可换行，不会出现横向溢出。

## 6. 具体实现

### `app/page.tsx`

在“先判断方向，比边做边改更省成本”这一段：

- 为 `SectionTitle` 增加 `descriptionClassName`
- 使用：
  - `text-copy`
  - `leading-7`
  - `whitespace-normal`
  - `md:max-w-6xl`
  - `md:whitespace-nowrap`

没有修改：

- `components/SectionTitle.tsx` 默认逻辑
- 其他 section 的说明宽度
- 标题层级和组件结构

## 7. 本轮优点

- 桌面端说明文字回到单行
- 移动端不受影响
- 不会给其他 section 带来连锁变化
- 首页标题区更紧凑、更克制

## 8. 本轮缺点与代价

- 这是局部收口，不是全局规则
- 如果后续同类区块还需要单行，需要继续按需覆盖

这个代价是可接受的，因为本轮目标就是最小改动地修正一个已确认的问题。

## 9. 验证与结果

本轮完成后执行：

- `npm run typecheck`
- `npm run build`
- `npm run dev`

重点确认：

- 桌面端单行
- 移动端自动换行
- 无横向滚动
- 标题与说明的宽度关系更自然

## 10. 本轮结论

这个问题的关键不是文案太长，而是默认说明容器太窄。

对首页这种“平台判断说明”来说，桌面端适合更宽、更稳的一行说明；而移动端仍然应该交给自然换行处理。

## 11. 下一轮建议

1. 如果首页还有其他说明句想做单行化，优先继续用局部 `descriptionClassName` 控制
2. 如果后续类似需求越来越多，再考虑是否给 `SectionTitle` 增加更明确的 `singleLineOnDesktop` 之类的轻量参数
