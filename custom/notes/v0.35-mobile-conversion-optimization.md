# 版本记录：v0.35-mobile-conversion-optimization

## 1. 本轮目标

本轮目标是在已经完成基础 mobile-first 收口的前提下，继续优化整站移动端的“转化节奏”和“信息密度”，让首页、详情页、方案页和诊断页更像真正面向手机决策的产品，而不是桌面版缩小。

本轮属于：

- 可维护性提升
- 转化路径优化
- 移动端阅读体验优化

## 2. 背景与上下文

本轮承接以下记录：

- `custom/notes/v0.34-image-rhythm-closure.md`
- `custom/notes/v0.33-launch-ready-mobile-closure.md`
- `custom/notes/v0.23-mobile-first-refinement.md`

在 `v0.33` 和 `v0.34` 之后，站点已经完成：

- 首轮 mobile-first 收口
- 图片存在必要性收紧
- CTA 基础统一

但从“移动端适配”到“移动端决策平台”之间，还差一层更细的优化：

- 首屏仍可再压缩
- 首页和详情页模块之间还可以更连续
- 一些说明语句对手机用户来说仍偏长
- 诊断页表单仍可更快进入动作状态

## 3. 问题分析

当前问题不是“页面能不能在手机上打开”，而是：

1. 手机用户是否能在 3 秒内看懂首屏
2. CTA 是否足够早、足够清晰
3. 页面滑动是否像连续信息流，而不是一屏一屏重新理解
4. 详情页是否适合持续阅读，而不是越看越累

也就是说，本轮优化的核心是“决策效率”，而不是“功能完整度”。

## 4. 候选方案比较

### 方案一：只改一两个首屏 class

核心思路：
只动 Hero 高度和按钮。

优点：

- 改动最少
- 风险最低

缺点：

- 无法解决 section 连续性
- 无法解决详情页阅读节奏
- 无法把诊断页真正压缩成移动端更高转化的形态

放弃原因：
不足以达到本轮“Mobile Conversion Optimization”的目标。

### 方案二：只在既有组件和页面骨架内微调信息密度、文案长度和移动端 class

核心思路：
不改结构，不新增复杂组件，只在指定页面和组件内压缩首屏、减少说明、提前 CTA、收紧留白。

优点：

- 能维持现有设计系统
- 改动边界清晰
- 可以同时解决首页、表单、详情页和 Footer 的移动端节奏问题

缺点：

- 需要重写部分页面文件，肉眼上改动会显得较多
- 要重新做一次 typecheck / build / dev 验证

最终选择原因：
这是在不重构前提下，收益最高的方案。

## 5. 最终决策

本轮采用方案二，具体原则：

1. 首页 Hero 继续压缩，让首屏只承担一个核心任务
2. 首页模块说明继续减量，减少手机端认知负担
3. CTA 位置不增加，但要更早、更清晰
4. 诊断页更快进入“判断 + 表单”节奏
5. 详情页减少块与块之间的松散感
6. Footer 继续收口，不保留任何拖沓信息

## 6. 具体实现

本轮实际修改如下：

- `components/HeroSection.tsx`
  - 将 balanced Hero 的移动端高度压到更稳定的 `78vh`
  - 标题再缩一档，减少首屏压迫
  - 副标题和 risk notice 行高继续收紧
  - CTA 上移，保证首屏触达更直接

- `components/SiteHeader.tsx`
  - Header 高度和 logo 再压一档
  - Drawer 宽度和内边距收紧
  - 菜单项纵向节奏更像移动产品

- `components/CtaBlock.tsx`
  - 文案缩短
  - 底部 CTA 区的移动端高度继续降低

- `components/Footer.tsx`
  - 整体纵向间距收紧
  - 品牌说明和联系方式进一步压缩
  - 保留最必要的产品型 Footer 信息

- `components/LeadCaptureForm.tsx`
  - 表单入口说明更短
  - 错误提示和步骤说明更直接
  - 第二步提交区更靠近核心动作
  - 整体更像“快速判断入口”

- `app/page.tsx`
  - 首页 Hero 文案继续压缩
  - 首页各 section 说明更短
  - 风险路径和案例矩阵区进一步减少移动端阅读负担
  - CTA 收口语句继续精简

- `app/diagnosis/page.tsx`
  - 风险说明和判断说明更短
  - 各模块间距进一步收紧
  - 页面更快进入表单主流程

- `app/knowledge/[slug]/page.tsx`
  - 头部和正文区块间距收紧
  - 正文段落节奏更适合手机连续阅读
  - 相关推荐与清单区之间的断层感减弱

- `app/solutions/[slug]/page.tsx`
  - 方案 Hero 辅助图高度略降
  - Breadcrumb 和正文间距继续压缩
  - 各内容区统一为更连续的移动端节奏

## 7. 本轮优点

本轮最直接的收益：

- 首页首屏更像决策入口，而不是展示页
- CTA 更早可见，且动作更明确
- 诊断页更快进入表单，不需要用户先读太多
- 详情页更适合长时间单手阅读
- Footer 终于完全脱离“信息坟场”气质

## 8. 本轮缺点与代价

本轮的代价主要有：

- 一些说明文本继续被压缩，表达空间变小
- 首页在移动端会显得更克制，展示感更弱
- 如果后续还要继续提升投流转化，可能需要基于真实数据做 A/B，而不是继续靠主观压缩

这些代价是可接受的，因为本轮目标是提升移动端决策效率，而不是增加展示内容。

## 9. 验证与结果

本轮计划执行：

- `npm run typecheck`
- `npm run build`
- `npm run dev`
- 本地移动端页面检查：首页、知识详情页、方案详情页、诊断页

本记录新增时，代码修改已完成，验证将在收尾阶段继续执行。

## 10. 本轮结论

本轮最重要的结论是：

移动端优化真正有效的部分，不是继续加适配规则，而是不断减少“第二优先级信息”，让首屏和滑动节奏始终围绕一个核心动作展开。

## 11. 下一轮建议

1. 用真实移动端宽度继续做一轮视觉复核，重点看 Hero 首屏、诊断页 sticky 提交区和 Footer 紧凑度
2. 如果准备正式投流，优先测试 Hero CTA 与中段 CTA 的点击差异
3. 后续如再优化，建议以埋点数据驱动，而不是继续主观压缩文案
