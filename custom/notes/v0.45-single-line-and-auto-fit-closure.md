# 版本记录：v0.45-single-line-and-auto-fit-closure

## 1. 本轮目标

本轮只做“文字单行化 + 版面自动适配”收口，不改结构，不新增组件。

重点目标：

- 让桌面端本来能一行展示的说明文字尽量回到一行
- 通过更合理的宽度、字号和比例收紧页面节奏
- 保持移动端正常换行，不出现横向滚动
- 让首页 Hero 左右节奏和风险卡高度更协调

本轮属于：

- 排版收口
- 信息密度优化
- 桌面端适配修正

## 2. 背景与上下文

本轮承接：

- `v0.44-homepage-subtitle-single-line-closure`
- `v0.43-navigation-minimalization-closure`
- `v0.41-hero-risk-panel-width-and-text-closure`

`v0.44` 已经验证了一个关键结论：

不是文案本身太长，而是很多说明文字被默认 `max-width` 误压窄了。

这轮把这个思路扩展到首页 Hero、多个 SectionTitle、方案页说明文字和首页右侧风险区，但仍然坚持“最小改动”和“移动端优先”的边界。

## 3. 问题分析

本轮开始前有四类问题：

1. 首页 Hero 说明文字桌面端被压成两行
2. 首页多个 section description 默认过窄，明明能单行却被折行
3. Hero 右侧风险卡区域宽度偏保守，标题容易过早换行
4. 方案卡和部分说明区的高度节奏不够整齐

真正的核心矛盾是：

桌面端宽度足够，但当前排版仍沿用偏窄的文本容器，导致页面看起来比实际更松、更拖。

## 4. 候选方案比较

### 方案 A：大量使用全局 `whitespace-nowrap`

优点：

- 可以快速让很多文字单行

缺点：

- 风险高
- 很容易伤到移动端
- 可能造成横向滚动

结论：

放弃。

### 方案 B：通过更合理的 `max-width`、`grid` 比例、字号和局部桌面单行规则收口

优点：

- 更稳
- 更符合“自动适配”目标
- 不依赖强行锁死布局

缺点：

- 需要针对不同区域分别调宽度和节奏

结论：

采用。

## 5. 最终决策

最终采取三层收口方式：

1. 轻微放宽 `SectionTitle` 默认说明宽度
2. 对首页关键说明句和方案页说明句做局部桌面单行优化
3. 继续放宽 Hero 右侧风险区，并压紧卡片内部排版

## 6. 具体实现

### `components/SectionTitle.tsx`

- 默认说明文字从 `max-w-2xl` 调整为：
  - `max-w-3xl`
  - `md:max-w-5xl`
  - `leading-7`

作用：

- 不做激进全局改动
- 但先把默认窄栏状态拉回更合理的桌面宽度

### `components/HeroSection.tsx`

- 桌面端 Hero 右栏从 `440px` 放宽到：
  - `lg:560px`
  - `xl:600px`
- 左侧说明文字区放宽到：
  - `md:max-w-5xl`
  - `md:text-[17px]`
  - `md:leading-normal`
  - `xl:whitespace-nowrap`
- 风险提示条最大宽度从 `max-w-2xl` 调整为 `max-w-3xl`

作用：

- 首页 Hero 说明文字更容易单行
- 右侧风险卡不再过早被挤压
- 左右高度关系更接近同一首屏系统

### `app/page.tsx`

对多个 `SectionTitle` 做局部说明宽度优化：

- `很多返工，不是评审时才发生`
- `大家通常怎么做错`
- `先看别人怎么提前发现风险`
- `先判断方向，比边做边改更省成本`
- `先看你更接近哪一种启动路径`

统一方向：

- `md:max-w-5xl` 或 `md:max-w-6xl`
- `md:text-[17px]`
- `md:leading-normal`
- 仅桌面大宽度使用 `xl:whitespace-nowrap`

作用：

- 桌面端尽量单行
- 移动端仍自然换行

### `components/RiskEntryCard.tsx`

- 卡片 padding 从 `p-4` 微调为：
  - `p-3.5`
  - 桌面 `lg:p-4`
- 标题字号压低到 `text-[14px]`
- 描述改为 `text-[15px]`、`leading-[1.5]`

作用：

- 在不继续扩结构的前提下，提高单行概率
- 保持四卡高度一致

### `components/SolutionCard.tsx`

- 方案卡标题增加：
  - `leading-snug`
  - `md:min-h-[3rem]`
- 方案卡摘要增加：
  - `md:min-h-[3.5rem]`

作用：

- 卡片高度更稳定
- 标题和摘要节奏更统一

### `app/solutions/[slug]/page.tsx`

为方案详情页几个说明区增加更宽的 description 样式：

- `真正决定能不能顺利推进的难点`
- `相关行业方案`
- `相关案例`

作用：

- 避免首页收紧后，方案页说明仍显得偏窄

### `components/Header.tsx`

本轮未再次改导航结构，继续沿用 `v0.43` 的单列轻菜单结果。

## 7. 本轮优点

- 首页桌面端说明文字更接近单行平台说明
- Hero 左右节奏更协调
- 风险卡更容易稳定在一行或更短的两行内
- 方案卡和内页说明区更整齐
- 仍然没有引入全局 `nowrap` 风险

## 8. 本轮缺点与代价

- 这是“局部 + 默认宽度轻调”的折中方案，不是一次性全局规则重构
- 部分文案在 1280 宽度下仍可能因字体渲染差异出现换行
- `build` 在上一轮已经出现过与 `/_not-found` 相关的异常，本轮验证时需要继续观察是否为环境态问题

## 9. 验证与结果

本轮完成后执行：

- `npm run typecheck`
- `npm run build`
- `npm run dev`

重点检查：

- 1440 / 1280 桌面宽度
- iPhone 13 / 常规安卓宽度
- 无横向滚动
- 首页说明文字不再突兀断行
- Hero 左右节奏更接近

## 10. 本轮结论

对当前站点来说，最有效的“单行化”方式不是强制锁死换行，而是：

- 给桌面更多合理宽度
- 把说明文字从窄栏里解放出来
- 在卡片区通过比例和字号微调降低断行概率

这样更符合“平台化、克制、自动适配”的目标。

## 11. 下一轮建议

1. 如果还要继续收紧，可优先检查首页案例区和行业方案区的标题长度是否需要再微调
2. 如果 `/_not-found` 构建异常继续出现，建议单独排查 Next 本地构建缓存与页面解析状态
3. 后续如需更系统化，可考虑给 `SectionTitle` 增加显式的桌面单行模式参数，而不是继续靠 class 覆盖
