# 版本记录：v0.5-content-route-closure

## 1. 本轮目标

本轮目标是在 v0.4 的 CNAS 专业内容平台结构确认后，做一次内容与路由收口优化，避免官网化表达、弱内容路由和诊断页转化不足的问题。

目标类型：内容收口、路由质量优化、验证复核。

## 2. 背景与上下文

本轮承接 `custom/notes/v0.4-cnas-content-platform-restructure.md`。上一轮已将网站定位调整为“CNAS专业知识与认可解决方案平台”，并完成分类、标签、FAQ、诊断页、文章模型和 SEO 结构。

本轮开始时再次执行 `git pull --ff-only`，仍因当前分支没有上游跟踪信息而失败，无法从 GitHub 拉取最新内容。

## 3. 问题分析

本轮主要检查三个风险：第一，是否仍残留“杭育科技官网化”表达；第二，是否存在无内容或弱内容页面被 sitemap 收录；第三，`/diagnosis` 是否更像启动前风险诊断转化页，而不是普通介绍页。

## 4. 候选方案比较

方案一：只运行验证，不改代码。

优点是无改动风险。缺点是无法处理空分类聚合页和诊断页转化强度不足，因此放弃。

方案二：删除分类动态页。

优点是避免弱内容页。缺点是会削弱后续内容扩展能力，因此不采用。

方案三：保留分类动态页，但只生成有文章的分类聚合，并让 FAQ 使用独立 FAQ 页面承接。

优点是保留长期扩展结构，同时避免 `/categories/cnas-faq` 这种空文章页被收录。最终选择该方案。

## 5. 最终决策

保留 `/cnas-faq` 和 `/faqs` 作为 FAQ 聚合入口；分类动态页 `/categories/[category]` 只生成有文章内容的分类。诊断页继续保留，并强化“适合启动”和“建议暂缓启动”的判断结构。

## 6. 具体实现

更新 `app/categories/[category]/page.tsx`，`generateStaticParams` 只返回有文章的分类；无文章分类访问时返回 `notFound()`。

更新 `app/sitemap.ts`，动态分类聚合只纳入有文章的分类，避免无内容页面进入 sitemap。

更新 `app/diagnosis/page.tsx`，新增“更适合启动的情况”“建议暂缓启动的情况”和“诊断后应形成什么判断”模块，让页面更偏 TEO 转化。

更新 `app/about/page.tsx` 的文件说明，移除“官网”字样，避免表达层面残留。

## 7. 本轮优点

sitemap 更干净，避免收录没有文章内容的分类页。

诊断页的判断导向更清晰，能更好承接“启动前风险诊断”需求。

全站复查未发现 `杭育科技提供`、`杭育有哪些`、`SNAS`、`认定`、`官网`、`其它业务`、`其他业务` 等不符合本轮要求的残留表达。

## 8. 本轮缺点与代价

当前只是通过静态规则避免空分类页，未来如果内容量增大，仍需要更系统的内容发布校验机制。

诊断页仍是静态转化页，尚未接入表单、CRM 或线索存储。

## 9. 验证与结果

已执行表达扫描，未发现指定风险词残留。

已执行 `npm run typecheck`，结果通过。

已执行 `npm run build`，结果通过。构建输出 48 个页面，分类聚合页不再包含无文章内容的 `cnas-faq` 分类。

## 10. 本轮结论

本轮完成了内容平台上线前的基础收口：专业表达更稳，诊断页更像转化页，sitemap 收录边界更干净。

## 11. 下一轮建议

第一，确认真实域名并替换 canonical 常量。

第二，补充更多长尾文章前，继续保持每篇文章的 GEO 结构。

第三，如需转化闭环，下一步优先做咨询表单与线索存储，而不是直接做复杂后台。
